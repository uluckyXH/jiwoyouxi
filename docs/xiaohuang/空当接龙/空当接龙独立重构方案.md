# 空当接龙独立重构方案 · 暖木牌室

记录日期：2026-09-18

状态：独立首版已实现并接入首页。下文保留设计目标；实际完成内容、取舍与检查范围见[暖木牌室实施与验证记录](暖木牌室实施与验证记录.md)。

追加确认：重点适配手机、折叠外屏、展开屏、半折叠与平板，提供清楚且稍响的音效。允许 Agent 按需开启模拟器验证；使用后关闭本任务启动的模拟器，保留原本已运行的其他任务实例，不重置其数据。

## 1. 这次做什么

以原生 ArkUI / ArkTS 重写空当接龙，让纸牌的可读性、移动手感与完整对局成为主角。视觉自主设计，融合 App 的奶油底色、温暖材质、圆润控件与浅深色外观，不沿用旧文档的场景构图，也不受旧 PNG 素材尺寸约束。

- 保留 52 张牌、四个空当、四个基础牌堆、八列牌列的核心玩法，以及撤销、提示、自动推进等已有能力。
- 场景、纸牌、花色、Logo、按钮图形、工具图标、帮助插图、暂停与结算装饰全部直接绘制 SVG。动态文字、点数、按钮与手势由原生组件负责。
- 声音清晰可闻，比当前 2048 的常用操作声更有存在感；移动与归位参考 2048 的短促、连贯动效，按纸牌的动作重新设计。
- 完整覆盖手机、折叠后的外屏、展开屏、半折叠、三折叠、平板和分屏窗口。空间不足时可以滚动继续玩。
- 新建代码和资源目录，旧版实现及其资源保留。正式游戏界面不出现“重构中”等开发文案。

## 3. 视觉方向与页面构图

### 暖木牌室

场景像窗边的一张小牌桌：奶油墙面、淡木纹边角、柔和的窗影，以及中央安静的绿毡。深色切换为墨绿牌桌和低亮度暖金细节。背景有完整设计，同时把清晰的数字、花色和牌列置于最高层级。

- 全窗口铺 App 基底色；窗影、木纹、叶枝分别作为 SVG 边角层定位，不把整张背景拉伸。
- 顶部为疏淡的斜窗影，底部为弧形桌沿和少量木纹；手机只保留边角，大屏增加侧边的牌盒和花色压印。
- 装饰逐渐淡回页面底色，上下安全区与内容区颜色连续，避免扫雷、2048 早期出现过的硬分界线。
- 棋盘内部不铺高对比纹理，不用大片浮动光点遮挡纸牌；背景静止，注意力留给当前操作。

### 纸牌与 SVG 细节

- 牌面约为 `1 : 1.42`，圆角随牌宽缩放。边缘用一条细描边、底部短阴影和极淡纸面高光表达厚度。
- 四种花色各画独立路径，统一视觉大小。红黑信息同时由花色形状表达；深色下黑色牌使用暖白墨色，仍保持两组花色的区分。
- 窄屏将左上角点数与小花色并排放在同一条露出区域，避免被下一张牌盖住。末张牌增加中央花色；大屏才展示更完整的点阵与右下倒置角标。
- J / Q / K 使用原创的简化侍从、冠饰与王冠徽记，不用 Emoji 或旧位图代替。装饰不能压过角标。
- 空当用四个浅凹槽，基础牌堆用四个花色槽；组名分别写“空当”“归位”，避免只靠位置猜用途。
- 选中牌轻抬、加实线边框；合法目标加柔和内框，非法目标轻回弹并显示短原因；不靠红绿闪烁单独传达状态。
- Logo 以叠放的 A 牌、四花色和小木框构成，先在小尺寸验证。后续接入时，新旧空当接龙入口共用这份新 SVG，原 Logo 文件和旧局内资源保留。
- 返回、声音、暂停、撤销、提示、自动整理、新牌局、帮助、关闭、继续等图标统一为圆角线条。按钮本体用原生圆角矩形或胶囊，图标直接使用 SVG。

## 4. 核心规则与完整对局

### 保留的规则

1. 一副不含大小王的 52 张牌全部正面朝上，分入八列，四个空当与四个归位槽初始为空。
2. 牌列按红黑交替、点数递减叠放；任意牌或合法牌组可以放到空列，仍受搬运能力限制。
3. 每个空当只放一张牌。基础牌堆按同花色 A→K 递增，只能收牌。
4. 成组移动只能搬动当前列底部连续、红黑交替递减的一段牌，不允许抽出中间单张。
5. 四种花色各归位 13 张才结算。局内分数由已归位数量乘 10 得出，撤销与重复移动不能刷分。

### 成组移牌能力

一次移动最多搬运 `(空当数 + 1) × 2^可辅助空列数` 张。计数采用移动前的状态，不能把搬走以后才空出的来源列算进去；如果目标本身是空列，它用于接牌，必须从可辅助空列数中排除。

例如有 1 个空当、1 个空列：搬到非空列最多 4 张；搬到那个空列最多 2 张。超限时显示“空当不足，先腾出位置”，同时指出当前可以搬几张，不只弹出“不能移动”。

### 操作与辅助

- **点选移动**：点一张可移动牌选择整段，再点合法目标完成；点原牌或桌面空白取消。小屏不用长距离精确拖拽也能完成所有操作。
- **拖动移动**：拖动时纸牌略微抬起，跟手显示，合法落点高亮；靠近棋盘滚动边缘时有限速滚动。点选与拖动共用同一个规则入口。
- **快捷归位**：双击仅执行合法归位，不悄悄选择另一个牌列；无法归位时保留选择并给轻提示。与拖动阈值区分，避免一次手势触发两种操作。
- **撤销**：恢复完整牌局、得分和步数，计时不倒退。记录最近 200 步，真实步数独立于历史容量。普通移动和每一步自动整理均可撤销。
- **提示**：标出来源与目标并说明理由，例如“红 7 可以接在黑 8 下方”。优先安全归位、腾出空当和露出牌；连续点击轮换建议。没有候选时不宣称“这局无解”。
- **自动整理**：保留旧版主动开启、随时停止的辅助。优先安全归位，再尝试有进展的合法牌列移动；自动归位采用保守条件，策略存在不确定性时停下交回玩家。记录访问过的牌面并限制一次推进长度，避免左右来回倒牌。按钮运行时明确变为“停止整理”，点牌或撤销立即停止。
- **无合法移动**：只有完整枚举确认没有合法动作时提示“暂时没有可走的牌”，保留撤销与重开入口，不直接认定整局不可解。
- **新牌局**：提供“重玩本局”“换一局”。已有进度时确认丢弃当前局，避免误触；重玩保持种子与发牌版本，换一局使用新种子。

计时在首次有效移动后开始；帮助、暂停、后台期间停止累积。计分继续保持旧版口径，界面重点展示归位进度、步数、用时，帮助中解释三者含义。

## 5. 玩法说明与新手反馈

保留 2048 已获认可的清晰分段指南，增加可直观看懂的纸牌示意：

1. **目标**：四个同花色牌堆，从 A 收到 K；显示 SVG 小牌组。
2. **牌列**：以黑 8 → 红 7 → 黑 6 展示合法排列，再给一个不能相接的例子。
3. **空当与搬运**：每格停一张，腾出空当或空列后能搬更多牌；点一下示例，播放一次短移动，不自动循环。
4. **操作与辅助**：点选 / 拖动 / 双击归位、撤销、提示、自动整理的作用与边界。

指南为原生可滚动面板，手机用底部圆角面板，大屏用居中面板；受折痕分隔时限于连续区域。关闭后回到原牌局与滚动位置。首次进入用一句“点选后再点目标，也可以拖动纸牌”，不强迫播放完整教程。

## 6. 多屏与折叠适配

布局输入为**当前窗口、安全区、所有可用折痕区域、字体缩放**，不根据设备名称猜尺寸。棋盘、命中区域和动画目标都由同一份布局结果计算。

### 空间分配

| 可用空间 | 布局与行为 |
| --- | --- |
| 普通手机、折叠后的外屏 | 顶栏与状态收紧，八列尽量一次显示，工具放底部；优先让出垂直空间给牌列 |
| 展开的折叠屏、平板竖屏 | 牌宽与露牌间距增大；宽度不适合侧栏时继续上下布局，不强制横排 |
| 宽屏且高度足够 | 八列棋盘在左，操作与说明在右；侧栏约 224–280 vp，棋盘主区至少约 576 vp，间距及安全边界计入后才能启用 |
| 半折叠、横屏矮窗口 | 根据实际空间缩短标题与状态区；横向折痕上下分区时，完整牌桌放在较合适的连续区域，工具可放另一侧，长列允许滚动 |
| 竖向折痕、三折叠 | 处理全部实际分隔区域，牌桌尽量放在能容纳八列的连续区域，其他区域承接工具；空间不足时仍能滚动，不把关键落点放在铰链上 |
| 极窄分屏或放大字体 | 保留最小可读牌宽和控件尺寸，提供棋盘双向滚动；不弹出“请展开屏幕才能玩”遮挡游戏 |

牌宽以可用棋盘宽度计算，初始约束为：`(棋盘宽度 - 两侧内边距 - 7 个列间距) / 8`，限制在 32–96 vp。普通窄屏内边距各 12 vp、列间距 4 vp；例如 360 vp 可用宽得到约 38.5 vp 的牌。宽屏逐步增加边距与间距，不能让额外容器内边距再挤掉一遍空间。小于最小内容宽时启用横向滚动，不让牌面越缩越小。

露牌高度按牌面与列长计算，角标区域至少约 20 vp；如果最高牌列超出视口则纵向滚动。空当和归位槽随棋盘横向同步，纵向保持在棋盘顶部可见；工具区不随长列滚走。狭窄牌列无法给每张牌提供 48 vp 的独立触点，因此不夸大触控范围，也不让相邻命中区相互覆盖：使用明确的列分区、露牌区域、选中放大预览和点选目标补足可操作性。

### 展开、收起、旋转时

- 游戏状态独立于布局，牌局、种子、步数、计时、撤销历史和开关原样保留。
- 牌与工具组件保持稳定身份，由一个布局结果更新坐标、尺寸；避免在不同父容器之间重建同一组操作按钮，重演 2048 的折叠后位置错误。
- 正在拖动的未提交动作取消，回到正确来源；已提交的动作落在最终逻辑位置，然后重新计算布局。重新布局期间不使用旧坐标判断落点。
- 自动整理在窗口变化时停下；不排队执行使用旧尺寸捕获的点击。新尺寸落定后立即允许继续操作。
- 连续尺寸事件合并处理，只应用最新布局；新旧布局过渡约 180–220 ms，持续拖拽窗口时优先跟随尺寸，不叠加多段动画。
- 重新计算滚动范围并夹紧偏移，优先保留当前牌列的位置；不因收起再展开保留一个超出范围的旧偏移。
- 监听窗口尺寸、安全区、显示与折叠变化。平整展开时不盲目把所有“折痕”当作不可用区域，依据平台实际遮挡和分隔信息处理；读取不到姿态信息时退回当前窗口的可用矩形。

## 7. 动效：顺滑，但不影响判断

参考 2048 的短移动、柔和落定和少量高光，纸牌采用自己的动作语义。以下为初始调校值：

| 动作 | 表现 | 目标时长 |
| --- | --- | --- |
| 新局发牌 | 按列错开发出，轻微位移与淡入；一次点击可直接完成 | 整体 600–800 ms |
| 选中 / 按钮 | 纸牌轻抬、边框出现；按钮压下后恢复 | 90–130 ms |
| 点选搬牌 | 整段牌沿短路径平移，阴影变化，落下时小幅回弹 | 160–210 ms |
| 拖动 | 移动中直接跟手；松开后吸附至目标 | 落定 120–170 ms |
| 归位 | 纸牌飞入同花色槽，槽边亮一次，进度轻增 | 180–240 ms |
| 不合法落点 | 原路返回，配一次轻微横摆与文字原因 | 140–180 ms |
| 撤销 | 使用反向移动回到原位置 | 160–200 ms |
| 提示 | 来源与目标边框各亮一次，小箭头示意移动方向 | 350–500 ms |
| 完成 | 四个花色依次亮起，少量纸屑或金色短光线，然后结算 | 700–1000 ms |

移动以规则提交后的状态为准，动画仅展示前后差异；每张牌有稳定 `cardId`，可观察的渲染位置不能困在旧闭包里。点按动画期间可保留一条用户意图，动画结束后按最新牌局重新验证；暂停、重开、撤销、窗口变化会清空意图和过期回调。拖动时只处理当前手势，不累积第二次拖动。

对局恢复、后台返回不重播发牌。支持系统减少动态效果时降低位移和弹性，功能不依赖动画完成才能结算。无循环漂浮、全屏模糊或逐帧重建 52 张牌。

## 8. 声音设计与音量

使用独立、本地的短音效，通过 SoundPool 播放；跟随 App 声音开关，局内也有可触达的开关。默认不加持续背景音乐。

| 事件 | 声音方向 |
| --- | --- |
| 选中 / 工具按钮 | 清楚、短促的木质轻点 |
| 移动与落牌 | 轻纸擦声加一个柔和落点，不能只有听不清的高频细响 |
| 成组搬牌 | 略厚的纸牌滑动声，整组只播放一次 |
| 归位 | 纸牌落点叠一枚明亮短音，同花色推进时可轻微升调 |
| 撤销 | 简短的反向滑动音 |
| 提示 | 两个柔和音符，不用警报音 |
| 无效操作 | 低音量轻扣，连续误触限频 |
| 完成 | 温暖短和弦，约一秒，不突然大声 |

制作目标是**同一设备、同一系统音量下，比当前 2048 的常用操作声稍响且更清楚**。不能只统一提高播放参数，也不能仅看波形峰值：先对实际素材的平均能量和瞬态做对齐，再调听感。初始将常用素材峰值控制在约 -6 至 -3 dBFS、播放增益约 0.9，保留混音余量，具体以生成后的波形与设备试听为准，这些不是已测结果。

常规一次动作只选择一个完整音效，最多叠两路并降低叠加增益；自动整理限制音效频率，不能每帧或每张粒子播放。关闭声音、暂停、退到后台或离开游戏时立即停止声音并取消延迟播放；不修改用户的系统媒体音量。资源加载失败也能正常游玩。

## 10. 性能与验证

牌局只有 52 张牌，普通移动只校验局部关系，无需常驻高频计算。主要风险在拖动重绘、自动整理搜索、窗口变化和异步回调，而不是规则计算量。

- 布局在牌列长度或窗口变化时计算；计时只更新对应文本，背景和全部牌面不随秒表重新生成。
- 移动修改涉及的牌列和渲染目标；静态 SVG 复用，不做每帧文件读取或重新解析。
- 提示按需枚举并限量返回；自动整理一次做一个动作，达到时间 / 步数预算或无进展就停止，不运行无边界全局求解。
- 拖动更新跟手位置，自动边缘滚动只在拖动且触边时运行；暂停、退场、折叠切换清理监听、定时器、动画和音频。
- 实施时测量单步规则、提示与连续拖动表现，再根据数据优化，不以“纸牌数量少”替代验证。

必要验证：

1. 52 张牌始终唯一完整；同种子可复现，可解发牌有实际可回放路径。
2. 四种花色、红黑递减、A/K 边界、空当占满、非法牌组；搬到空列 / 非空列的不同容量以及来源不能提前算空列。
3. 撤销超过历史容量后的正确步数、得分和状态；连续撤销、重新开局和重复归位不会刷分。
4. 提示保证合法；自动整理遇到循环、无进展和预算上限会停，用户可立即接管。
5. 动画中撤销、退出、暂停、换局、连点、切主题、切尺寸；画面、牌值、命中位置与最终规则状态一致。
6. 存档恢复、损坏数据、延迟写入、后台返回、完成后恢复，不重复计局或上报成就。
7. 布局样本至少覆盖 320×568、360×800、412×915、600×480、720×840、840×720、1024×768、1280×800 vp；另覆盖可用高度不足、字体放大与长列。
8. 窗口连续收起→展开→收起、多次横竖旋转、横折痕、竖折痕、多折痕、拖牌中切姿态；全部操作按钮可触达，滚动与落点正确。
9. 浅深色的所有纸牌、按钮、背景、帮助、暂停、结算与系统安全区一致，无硬分界；SVG 图标不能缺失或糊成字符占位。
10. 音效文件可解码、无削波、开关即时生效，自动整理不叠成噪声；手机、平板的实际音量待用户设备试听。
11. ArkTS 编译及原生构建通过，旧游戏目录和路由无意外修改。自动检查与用户在设备上的页面 / 手感验收分别记录，不将计算测试称为设备实测。

## 11. 后续实施顺序

1. **规则与对局**：独立模型、可解发牌、目标相关的搬运上限、动作事务、撤销与存档；先验证规则边界。
2. **SVG 与原生牌桌**：完成浅深色背景、牌面、花色、Logo、工具图标；搭建点选、拖动、状态栏、指南和弹窗。
3. **多屏与动效**：先覆盖全部尺寸和折叠切换，再接入稳定身份的移牌、归位、撤销和结算动效；补齐手势 / 滚动冲突处理。
4. **音效与 App 接入**：制作稍响且有层次的声音，接入设置、返回、存档、成就与首页；完成规则、生命周期和构建检查后，由用户查看页面与试听。

当前方案不启动石头剪刀布重构。其后续基准已明确为 `games/rpsBattle/` 的“鸡窝乱斗”；本轮隐藏的是 `rps` 的“观战 · 策略”首页入口，详见[总规划](../App与游戏重构规划.md)。
