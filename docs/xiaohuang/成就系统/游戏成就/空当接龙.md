# 空当接龙成就设计

状态：草案，待逐项确认
游戏 ID：`freecell`
代码入口：`entry/src/main/ets/games/freecell/FreecellPage.ets`

关联：[成就系统文档索引](../文档索引.md)。

## 1. 设计目标

空当接龙的成就应围绕“真正通关、走得精、走得快”展开。首期不把提示、自动推进、撤销等辅助操作变成羞辱或惩罚条件，因为当前版本没有稳定的辅助使用统计，且它们本身是正常体验的一部分。

## 2. 当前可用玩法事实

| 事实 | 当前代码来源 | 是否可直接上报 | 备注 |
| --- | --- | --- | --- |
| 是否通关 | `checkWin()` 中的 `isWon(gameState)` / `won` | 是 | 四个基础牌堆归位时触发，`settled` 防止重复结算。 |
| 当前 / 最终步数 | `moves`、`history.length` | 是 | 每次有效移动后更新。 |
| 用时 | `elapsed` | 是 | 首次移动后计时；玩法说明和离开确认显示时暂停计时。 |
| 最终得分 | `currentScore()` | 是 | 由四个 foundation 的牌数计算，通关时为固定完整值，不适合做难度成就。 |
| 是否使用提示、自动推进、撤销 | 仅有局部 UI 状态 / 行为 | 否 | 当前没有稳定、可结算的累计字段。 |

当前只在 `checkWin()` 通过 `recordScore(currentScore())` 记录分数，因此没有“失败结算”。首期空当接龙成就都以真实通关为前提，这与当前游戏流程一致。

## 3. 首期成就草案

| ID | 名称 | 玩家感受 | 达成规则 | 类型 / 触发时机 | 勋章文件 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| `freecell.complete_board` | 四花归位 | 第一次完整通关 | `won = true` | 结算型；通关结果层出现后 | `ach_freecell_complete_board.png` | 建议确认。 |
| `freecell.efficient_win` | 精打细算 | 用较少步数整理完一局 | `won = true` 且 `moves <= FREECELL_EFFICIENT_WIN_MAX_MOVES` | 结算型；通关结果层出现后 | `ach_freecell_efficient_win.png` | 阈值待校准。 |
| `freecell.quick_win` | 疾速清台 | 在合理时间内通关 | `won = true` 且 `elapsed <= FREECELL_QUICK_WIN_MAX_SECONDS` | 结算型；通关结果层出现后 | `ach_freecell_quick_win.png` | 阈值待校准。 |

两个挑战阈值都必须基于真实可解局样本校准。先记录至少一批普通玩家、熟练玩家和辅助操作场景的通关步数 / 用时，再设定“有挑战但不逼近极限”的门槛。

## 4. 触发与通知

```text
isWon(gameState) 变为 true
  -> FreecellPage.checkWin()
      -> 停止计时和自动推进，显示通关结果层
      -> 构造 GameSessionResult（won、moves、elapsed、score）
      -> Index.ets 判定并落盘
      -> 通关结果层稳定后播放新成就鸡窝勋章
```

- 三条都是结算型成就，不在每步移动时做判定，也不在拖牌过程中弹提示。
- 本局同时满足少步和限时通关时，通知进入统一队列；结果层需显示“本局新成就”回看区。
- 返回大厅、重新开局、撤销到未通关状态都不能触发成就；`settled` 继续作为“只结算一次”的本地保护。
- 提示、自动推进与撤销暂不影响三条成就资格；若未来要增加“无提示通关”，必须先增加正式、可测试的 `hintUsed` / `autoCompleteUsed` 事实。

## 5. 需要新增的数据与测试

| 项目 | 需求 |
| --- | --- |
| 结算接口 | `checkWin()` 构造一次正式 `GameSessionResult`，同时保留高分更新兼容。 |
| 阈值常量 | 在 `AchievementRegistry` 声明步数与秒数阈值，禁止写在 `FreecellPage.ets`。 |
| 会话 ID | 开局时生成稳定 `sessionId`；同一次通关回调不得重复累计。 |
| 单元测试 | 覆盖未通关、刚好达标、超过阈值、重复通关回调和旧存档补发。 |
| 真机验证 | 验证通关动画、结果层、顶部鸡窝勋章和底部按钮不会相互遮挡。 |

## 6. 待确认项

- 少步与限时的校准阈值。
- 是否保留提示 / 自动推进也能获得挑战成就；当前推荐保留，避免把辅助功能变成隐形惩罚。
- 是否未来增加“连续通关”或“无撤销通关”；首期不做，当前缺稳定事实与充分样本。
