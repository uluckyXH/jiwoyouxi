# 石头剪刀布大作战成就设计

状态：草案，待逐项确认
游戏 ID：`rpsBattle`
代码入口：`entry/src/main/ets/games/rpsBattle/RpsBattlePage.ets`

关联：[成就系统文档索引](../文档索引.md)、[高光翻盘与玩家干预机制迁移设计](../../石头剪刀布大作战/高光翻盘与玩家干预机制迁移设计.md)。

## 1. 设计目标

新版石头剪刀布大作战的成就应奖励玩家“看懂战局、选对阵营、见证精彩乱斗”，而不是逼玩家为了刷成就频繁改机制或拉满人数。首期只做三条：完成首局、支持成功、见证高转换战局。

不把旧版 `rps` 的战报、悬赏或锦标赛概念混进本页。旧版和新版虽然显示名称相同，但成就 ID 必须保持不同命名空间。

## 2. 当前可用玩法事实

| 事实 | 当前代码来源 | 是否可直接上报 | 备注 |
| --- | --- | --- | --- |
| 对局结束原因、赢家 | `RpsBattleResult.finishReason`、`winner` | 是 | 支持清场、到时、据点和可能平局。 |
| 玩家支持的阵营是否胜利 | `RpsBattleResult.supportWon` | 是 | 由规则层比较赢家与 `supportFaction` 生成。 |
| 单局转换总数 | `RpsBattleResult.conversions` | 是 | 引擎的 `conversionCount()` 已在结果中保存。 |
| 用时、最终三方人数、得分 | `elapsedSec`、`counts`、`score` | 是 | 可供后续扩展，首期不以高分为核心条件。 |
| 是否使用上帝之手干预 | `isInterventionMatch` | 是 | 当前只要开启上帝之手即标记为干预局。 |
| 玩法模式、规模、机制选择 | `RpsBattleOptions` / 页面选择状态 | 需要随结果补传 | 当前 `RpsBattleResult` 未保存 `modeKey` 等配置；首期三条不依赖它。 |

当前 `RpsBattlePage.finishGame()` 只会在结果有正分且非干预局时调用 `recordScore`。成就接入后必须改为无论胜负或平局都上报一次正式 `GameSessionResult`，否则“完成首局”会漏掉平局，也会把成就逻辑错误绑定在最高分上。

| ID | 名称 | 玩家感受 | 达成规则 | 类型 / 触发时机 | 勋章文件 | 状态 |

| `rpsBattle.conversion_storm` | 转化风暴 | 见证一次足够热闹的阵营翻转 | `conversions >= RPS_BATTLE_CONVERSION_STORM_TARGET` | 结算型；结果层稳定后 | `ach_rps_battle_conversion_storm.png` | 阈值待校准。 |

`RPS_BATTLE_CONVERSION_STORM_TARGET` 先不要写死。应按小局、标准、大局和四种模式采集真机结果分布后再确定一个常规玩家可达、但不是每局都达成的数值。首期建议使用统一阈值；若各模式差异明显，再改为由模式配置声明阈值。

## 4. 正式局与触发规则

### 4.1 推荐的首期口径

- `初入战场`：所有非开发、非自动演示的完整对局都算，包括平局；它是入门成就，不应因玩家支持失败而漏记。
- `押中阵营`：推荐只在非干预局中解锁。上帝之手会改变最终结果，首期不让它影响“猜对”的可信度。
- `转化风暴`：推荐只在非干预局中解锁，避免手动干预把转换数变成刷取目标。
- 退出到大厅、还在 `setup` / `countdown` 的局、未形成结果的中断局，不上报正式结算也不解锁成就。

是否让“初入战场”在开启上帝之手时也可解锁，是待确认的产品选择。推荐允许：它只表达玩家完成第一局，并不宣称技术或预测能力。

### 4.2 上报时机

```text
RpsBattleEngine 得到 RpsBattleResult
  -> RpsBattlePage.finishGame(result)
      -> 构造 GameSessionResult（赢家、支持结果、转换数、用时、是否干预）
      -> Index.ets 判定并落盘
      -> 结果层出现并稳定后，若有 newlyUnlocked 再播放鸡窝勋章
```

不在战斗帧循环里上报转换事件。`conversions` 只在 `finishGame()` 读取最终值；这样不会每次碰撞都触发成就判定，也避免影响 Canvas 性能。

## 5. 需要新增的数据与测试

| 项目 | 需求 |
| --- | --- |
| 结算接口 | 将 `recordScore(score)` 扩展为单次 `recordGameResult(result)`；平局也要上报。 |
| 正式局标记 | 明确 `isInterventionMatch`、开发模式和未来自动演示局的处理；不可只依赖分数是否大于 `0`。 |
| 阈值常量 | 在 `AchievementRegistry` 声明 `RPS_BATTLE_CONVERSION_STORM_TARGET`，而不是写在页面。 |
| 单元测试 | 覆盖首次对局、支持胜利、支持失败、平局、干预局、转换数刚好达标和重复事件。 |
| 真机验证 | 覆盖经典乱斗、团队占点、小心叛徒、众生平等各至少一局，观察结果层和通知不重叠。 |

## 6. 待确认项

- 转化风暴的最终阈值，以及是否按不同模式分档。
- 开启上帝之手后，哪些入门成就仍可获得；建议只保留“初入战场”。
- 是否以后追加“占点翻盘”“绝地复活”等模式专属成就；首期不加入，避免让四种模式的规则与成就同时膨胀。
