# 鸡窝 2048 成就设计

状态：草案，待逐项确认
游戏 ID：`chicken2048`
代码入口：`entry/src/main/ets/games/chicken2048/Chicken2048Page.ets`

关联：[成就系统文档索引](../文档索引.md)。

## 1. 设计目标

2048 的高光非常明确：玩家把方块一步步合大。首期三条成就直接对应 `256`、`1024`、`2048` 三个里程碑，所有判定都基于最大方块，绝不拿总分替代。

## 2. 当前可用玩法事实

| 事实 | 当前代码来源 | 是否可直接上报 | 备注 |
| --- | --- | --- | --- |
| 本局最高方块 | `maxTile` / `moveChicken2048Tiles(...).maxTile` | 是 | 每次有效滑动后更新。 |
| 本次合成事件 | `Chicken2048MoveResult.merges` | 是 | 可判断阈值是否在本次滑动首次跨越。 |
| 本局得分、有效步数 | `score`、`movesMade` | 是 | 首期仅作为结果展示与后续扩展事实。 |
| 达到 2048 目标 | `reachedTarget`、`won`、`showWinOverlay` | 是 | 当前达成后可选择继续冲更高数字。 |
| 开发棋盘 / 测试局 | `triggerDevTarget`、`triggerDevLargeTiles`、`applyDevBoard` 等 | 存在但需隔离 | 当前隐藏开发工具可直接摆出大数字，不能产生成就。 |

当前 `recordScore` 在失败结算或带进度离开时记录，达到 2048 本身不会立即记录。因此，成就不能依赖现有 `recordScore`，而必须在正常滑动产生目标方块时上报即时玩法事实。

## 3. 首期成就草案

| ID | 名称 | 玩家感受 | 达成规则 | 类型 / 触发时机 | 勋章文件 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| `chicken2048.reach_256` | 合成小能手 | 第一个值得庆祝的大方块 | 本次正式滑动前 `maxTile < 256`，本次后 `maxTile >= 256` | 高光型；合成脉冲结束后 | `ach_chicken2048_reach_256.png` | 建议确认。 |
| `chicken2048.reach_1024` | 千格高手 | 冲到进阶里程碑 | 本次正式滑动前 `maxTile < 1024`，本次后 `maxTile >= 1024` | 高光型；合成脉冲结束后 | `ach_chicken2048_reach_1024.png` | 建议确认。 |
| `chicken2048.reach_2048` | 2048 达成 | 达到本局核心目标 | 本次正式滑动前 `maxTile < 2048`，本次后 `maxTile >= 2048` | 高光型；原有“合成 2048！”结果层稳定后 | `ach_chicken2048_reach_2048.png` | 建议确认。 |

同一次滑动理论上可能跨过多个目标。引擎可以一次返回多条 `newlyUnlocked`，但通知队列必须按顺序展示；`2048 达成` 优先等现有胜利层出现后再展示，不能盖住合成反馈。

## 4. 触发与正式局规则

```text
玩家完成一次有效滑动
  -> moveChicken2048Tiles 返回 result.maxTile 和 merges
  -> 页面更新棋盘、分数、合成脉冲
  -> 比较滑动前后最大方块，构造 milestone 事件
  -> 原有合成动画结束后，Index.ets 判定并播放鸡窝勋章
```

- 事件只在“本次滑动首次跨越阈值”时上报；不是每一帧或每次读取 `maxTile` 都上报。
- `256`、`1024` 在本次合成脉冲和分数变化稳定后可显示普通 / 高光鸡窝勋章。
- `2048` 先保留当前胜利结果层的主视觉；结果层稳定后再显示鸡窝勋章，避免两个庆祝动画抢同一瞬间。
- 从大厅离开、失败结算和恢复历史棋盘都不补发即时提示；成就的持久化状态仍由引擎去重。

### 4.1 开发工具隔离

调用任何 `applyDevBoard(...)` 路径时，本局必须设为 `isOfficialSession = false`。该标记应在本局内不可逆，且：

- 不报告 `reach_256` / `reach_1024` / `reach_2048` 事件。
- 不更新成就进度或解锁时间。
- 不播放鸡窝勋章、音效或震动。
- 可保留用于视觉验收，但在测试报告中必须标为开发局。

## 5. 需要新增的数据与测试

| 项目 | 需求 |
| --- | --- |
| 会话状态 | 新增 `sessionId` 与不可逆 `isOfficialSession`；开发棋盘必须改为非正式局。 |
| 事件构造 | 记录移动前的 `previousMaxTile`，只为首次跨越的阈值构造 `GameAchievementEvent`。 |
| 展示延迟 | 复用已有合成 pulse 的结束节点或安全延迟，不能在 `inputLocked` / 触摸滑动中直接弹出。 |
| 单元测试 | 覆盖刚好合成 256、跨越多个阈值、已解锁重复事件、开发棋盘、达到 2048 后继续游戏。 |
| 真机验证 | 验证快速连续滑动、合成动画、胜利层、通知队列和顶部安全区不会互相遮挡。 |

## 6. 待确认项

- 三个标题是否采用当前草案；它们不带数字，但成就页条件会明确显示最大方块目标。
- `256` 是否值得保留为首个成就；当前推荐保留，因为它给新玩家一个早期可达的正反馈。
- 2048 后继续冲高数字时，首期不新增 `4096` 等成就，先观察达成率与素材节奏。
