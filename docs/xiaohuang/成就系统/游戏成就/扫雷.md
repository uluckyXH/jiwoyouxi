## 1. 设计目标

扫雷成就的重点是“平安排雷、快速判断、正确插旗”。首期不奖励盲目点击次数或失败次数，也不让开发用的看雷功能污染正常成绩。

“旗开得胜”不能仅要求“没用过插旗模式”，也不能在胜利后读取被自动补齐的旗帜。推荐规则是：玩家本局至少插过指定数量的旗（阈值待定），且每次主动插旗都落在真实雷格上；若任何一次在非雷格插旗，即使之后取消，也失去资格。

## 4. 难度、正式局与触发规则

### 4.1 迅捷排雷的范围

首期建议只选一个固定难度作为比较口径，优先默认简单难度。理由是不同雷区规模的时间不能直接横比，固定口径才能让玩家理解目标，也便于真机校准。

备选方案待确认：

1. **推荐：简单难度限定。** 文案明确为“在简单雷区内迅捷排雷”。
2. 分难度分别设置阈值。体验更完整，但会增加更多规则、素材与测试量。
3. 使用标准化分数。当前没有适合的统一分数模型，不建议首期采用。

### 4.2 正式局规则

- 首次翻格后才是正式开始；未开始就回大厅不构成结算。
- 开启 `devRevealMines` 的局必须立刻标记为 `isOfficialSession = false`，即使后来关闭看雷也不得恢复资格。
- 失败、退出和重开不解锁首期扫雷成就。
- 胜利触发点在 `finish(true)`；先显示既有胜利结果层，再播放顶部鸡窝勋章。

## 5. 需要新增的数据与测试

| 项目 | 需求 |
| --- | --- |
| 正式局字段 | 新增不可逆 `isOfficialSession`，开发看雷或未来测试操作触发后置为 `false`。 |
| 插旗事实 | 新增 `manualFlagCount`、`hasEverFlaggedNonMine`；只在玩家主动切换旗帜时更新，不能受 `flagAllMines()` 影响。 |
| 结算结果 | 上报 `win`、`elapsed`、`difficultyKey`、`openedSafeCells`、插旗事实、正式局标记。 |
| 阈值 | 用真机样本确定默认难度的快速清场秒数和完美插旗最低旗数。 |
| 单元测试 | 覆盖首点安全、胜利、失败、看雷局、插错再撤销、自动补旗和重复结算。 |
| 真机验证 | 验证胜利羽毛 / 结果层先完成，再显示鸡窝勋章，且不会挡住再来一局 / 回大厅。 |

## 6. 待确认项

- 快速清场是否只限定简单难度；当前推荐是。
- 完美插旗要求的最小主动插旗数量。
- 是否允许使用暂停后仍取得迅捷排雷；当前计时已在暂停时停止，首期建议允许，除非以后要专门做竞速模式。
