# 俄罗斯方块成就设计

状态：草案，待逐项确认
游戏 ID：`tetris`
代码入口：`entry/src/main/ets/games/tetris/TetrisPage.ets`

关联：[成就系统文档索引](../文档索引.md)。

## 1. 设计目标

俄罗斯方块的首期成就奖励清行瞬间和持续推进，而不是只看最后分数。三条分别对应第一记四消、累计消行和速度等级提升，玩家能从棋盘变化中立刻理解自己为什么达成。

## 2. 当前可用玩法事实

| 事实 | 当前代码来源 | 是否可直接上报 | 备注 |
| --- | --- | --- | --- |
| 单次消行数 | `finishClearing()` 中的 `cleared` / `lastClear` | 是 | 清行扫光结束后才得到最终行数。 |
| 连消数 | `combo` | 是 | 当前可供后续扩展，首期不单独立项。 |
| 累计消行 | `lines` | 是 | 每次清行后累加。 |
| 当前等级 | `level = speedLevelForLines(lines)` | 是 | 每 `20` 行升一级，等级 3 对应累计 `40` 行。 |
| 分数 | `score` | 是 | 继续记录高分，但首期不拿分数代替清行事实。 |
| 游戏结束 | `finishGame()` | 是 | 当前在 game over 时记录分数。 |

`finishClearing()` 是唯一适合报告清行成就的地方：此时已有原清行动画结束后的实际 `cleared`、`lines` 与 `level`，不会在方块仍落下或棋盘仍在扫光时提前判断。

## 3. 首期成就草案

| ID | 名称 | 玩家感受 | 达成规则 | 类型 / 触发时机 | 勋章文件 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| `tetris.first_tetris` | 第一记四消 | 首次一次消掉四行 | 正式局中任一次 `cleared === 4` | 高光型；`finishClearing()` 完成后 | `ach_tetris_first_tetris.png` | 建议确认。 |
| `tetris.twenty_lines` | 连消好手 | 单局持续清行 | 正式局中 `lines >= 20` 首次成立 | 高光型；对应清行稳定后 | `ach_tetris_twenty_lines.png` | 建议确认。 |
| `tetris.level_three` | 方块掌控 | 进入更快的速度档 | 正式局中 `level >= 3` 首次成立，即累计至少 `40` 行 | 高光型；升级对应清行稳定后 | `ach_tetris_level_three.png` | 建议确认。 |

三条均为本局事实，不要求玩家必须 Game Over 后才算数。达到目标后即使后来失败或退出，成就仍然保留；这更符合“已经打出一次四消 / 已经达到等级”的玩法真相。

## 4. 触发与通知

```text
锁定方块 -> 触发清行扫光 -> finishClearing()
  -> 得到 cleared、lines、level、combo
  -> 仅在首次跨过本局阈值时上报即时事件
  -> 棋盘完成重排并生成下一个方块后，播放鸡窝勋章
```

- `第一记四消` 必须在 `cleared === 4` 时上报，不能使用累计分数或 `lines` 推断。
- `连消好手` 与 `方块掌控` 比较清行前后的 `lines` / `level`，避免每一次清行重复发送同一事件。
- 如果一次清行同时跨过 `20` 行和等级 3（通常不会，因等级 3 需要 40 行），仍通过全局通知队列排序显示。
- 通知必须等清行扫光、棋盘重排与新方块生成完成后出现；不能遮挡底部四键控制，也不能吃掉长按输入。
- 退出、暂停、开发 / 自动演示路径如果未来存在，必须标记非正式局；当前没有专门开发棋盘，但接口仍预留这一边界。

## 6. 待确认项

- “等级 3”是否保留。当前规则中它等于 `40` 行，具备明确挑战感；若试玩过长，可改为等级 2 或改成连击成就。
- 是否要以 `combo >= N` 替换其中一条；当前推荐保留等级成就，因为其规则更稳定、更容易理解。
- 未来是否增加“高分破纪录”类成就；首期不用分数，避免与大厅高分展示重复。
