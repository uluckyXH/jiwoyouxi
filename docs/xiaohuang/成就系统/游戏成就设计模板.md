# 游戏成就设计模板

状态：后续新增或扩展游戏时复制使用
更新时间：2026-08-24

每个上架游戏都需要独立成就设计文档。文档先证明“当前代码能够给出哪些可靠事实”，再决定成就名称和阈值；不以临时 UI 文案、截图或猜测作为解锁依据。

## 模板

```markdown
# <游戏名>成就设计

状态：草案 / 已确认 / 已实现
游戏 ID：`<gameId>`
代码入口：`entry/src/main/ets/games/<gameId>/...`

## 1. 设计目标

- <首期只做 3 条成就的体验目标>

## 2. 当前可用玩法事实

| 事实 | 当前代码来源 | 是否可直接上报 | 备注 |
| --- | --- | --- | --- |
| <won / score / maxTile> | <文件和方法> | 是 / 否 | <风险> |

## 3. 首期成就草案

| ID | 名称 | 玩家感受 | 达成规则 | 事实字段 | 时机 | 勋章文件 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |

## 4. 触发与通知

- 正常结算：<何时构造 GameSessionResult>
- 高光瞬间：<何时构造 GameAchievementEvent>
- 禁止条件：<开发工具、退出、重复事件、非正式局>

## 5. 后续实现清单

- <需要新增的指标、状态、测试>

## 6. 待确认项

- <阈值、名称、素材、是否支持某个玩法模式>
```

## 必填规则

- 首期每款游戏最多 3 条：首次 / 核心玩法 / 挑战或里程碑各一条。
- `ID` 使用 `<gameId>.<rule>`，一旦确认不改名、不复用。
- 每条必须明确为“结算型”或“高光型”。结算型在结果层稳定后提示；高光型必须等原有动画完成后提示。
- 调试按钮、开发棋盘、隐藏测试入口、自动演示和非正式局必须不能产生成就。
- 阈值类成就在文档阶段标为“待校准”，直到有真机样本和测试报告。
- 每项成就都要对应[成就勋章素材绘制提示词](成就勋章素材绘制提示词.md)中的一个文件名；不直接把标题画在图里。

## 确认状态定义

| 状态 | 含义 |
| --- | --- |
| 草案 | 名称、规则或阈值仍可调整，不能直接开发。 |
| 已确认 | 产品规则与素材主题已经确定，可以实现。 |
| 已实现 | 已完成结算 / 高光事实接入、纯规则测试、真机验证和测试报告。 |
