## 工作约定

- 每份游戏文档先描述当前代码能够稳定提供的玩法事实，再讨论成就；不能为了一句好听的文案凭空假设数据已经存在。
- 成就 ID 一旦确认就稳定使用 `gameId.rule`；标题、说明和勋章图可以迭代，ID 不复用。
- 时间、步数、转换数等平衡阈值先标记为“待校准”，从真机样本中确定；不在第一轮文档里拍脑袋写死。
- 勋章图片只提供核心图形，锁定态、金框、勾选、日期和进度由 ArkUI 绘制；不要为每个状态额外画一套图片。
- 游戏页只上报玩法事实，不能直接解锁成就、直接访问 `preferences` 或各自显示通知。
- 每次确认一款游戏后，先更新对应文档与素材清单，再开始实现该游戏的结算上报、纯规则测试和真机验证。
