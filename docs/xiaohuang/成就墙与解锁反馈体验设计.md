# 成就墙与解锁反馈体验设计

日期：2026-08-26
状态：首期产品与交互方案；独立成就墙与通用提醒底座已实现，尚未接入游戏事实上报

关联文档：[成就系统统一设计方案](成就系统统一设计方案.md)。前者定义数据、规则、存档和接入契约；本文收敛首期六款游戏的成就内容、成就墙视觉，以及玩家游玩时的解锁反馈。

成就墙的页面线框、徽章视觉、游戏内“鸡窝勋章”的布局与 ArkUI 实现选型，见[成就界面与游戏内提醒鸿蒙原生设计](成就界面与游戏内提醒鸿蒙原生设计.md)。

实现说明：本轮只实现应用壳中的通用提醒能力，不改 `games/**`。因此成就墙读取真实独立状态，但当前没有游戏会产生解锁或显示通知；每款游戏仍需按本文的“展示时机”逐个接入事实。

## 1. 首期范围与结论

成就不应只是在大厅里摆一组“已完成 / 未完成”的静态条件。首期应做成一套真实的离线成就系统：游戏页只上报玩法事实，合集壳统一判定、存档、展示和通知。

当前大厅有旧版 `rps` 与新版 `rpsBattle` 两个同名入口。为避免同名入口让成就归属混乱，首期按下面六款主推游戏设计：

1. `rpsBattle`：石头剪刀布大作战新版。
2. `freecell`：空当接龙。
3. `minesweeper`：扫雷。
4. `chicken2048`：鸡窝 2048。
5. `tetris`：俄罗斯方块。
6. `suika`：鸡窝水果摊。

旧版 `rps` 继续保留为玩法对照和兼容入口，但首期不新增其专属成就，也不与 `rpsBattle` 共享任何成就 ID。以后若决定继续运营旧版，应使用独立的 `rps.*` 成就键单独接入。

首版数量控制在约 22 条：每款游戏 3 条，共 18 条；再加 4 条合集里程碑。这个规模足够让成就墙有收集感，又不会把轻量小游戏变成任务清单。

- `2048 达成` 必须以最大方块为依据，不能以总分代替。
- 时间、步数、转换数、消行数等阈值在真机试玩数据出来前不写死；先记录事实，再用合理样本校准。
- 需要“正确插旗 / 无误插旗”的扫雷成就，应先补稳定的玩法事实；没有可靠事实前不能由 UI 状态或猜测推断。
- 调试棋盘、自动演示和测试脚本必须标记为非正式会话，不得产生永久成就。

## 3. 成就墙布局

成就墙保留在大厅底部 Tab 中，但从当前的静态列表升级为可扫读的成就档案。页面不做新的大横幅，保持“鸡窝游戏”轻松、温暖且紧凑的视觉层级。

```text
成就墙                                      已解锁 8 / 22
████████████░░░░░░░░

[ 全部 ] [ 已解锁 ] [ 进行中 ]

合集里程碑
 [鸡窝徽章]  鸡窝开张                已解锁 · 2026-08-24
 [羽毛徽章]  常驻鸡仔                6 / 10 局  ─────

石头剪刀布大作战
 [Logo + 星] 初入战场                完成任意一局
 [Logo + 旗] 押中阵营                已解锁

俄罗斯方块
 [Logo + 皇冠] 第一记四消            未达成
```

### 3.1 布局规则

- 顶部标题行右侧只显示紧凑的“已解锁 X / Y”，标题下使用细进度条；不使用抢眼的大百分比或第二个 Banner。
- 使用原生 `Tabs` 或分段控件筛选“全部 / 已解锁 / 进行中”，默认展示“全部”。
- 合集里程碑固定在最前；游戏分组按大厅的主推顺序排列。
- 每个游戏组标题使用现有游戏 Logo、游戏名和主题色。Logo 是分组身份，不需要为每条成就重画插画。
- 单条成就是一行轻卡片，而非卡片中再嵌卡片：左侧徽章，中间为标题与条件 / 进度，右侧为解锁日期、完成态或未达成状态。
- 有进度的项目显示“当前 / 目标”和细进度条；一次性项目显示明确的达成条件，不能把内容藏成问号。
- 点击条目才打开底部半模态详情，展示完整条件、来源游戏、解锁日期和进度；游玩过程中不强制弹出详情。

### 3.2 徽章与图标语言

首版不为 22 条成就逐一制作复杂位图插画。统一实现一个 `AchievementBadge`，既有辨识度，也方便新增成就。

- 尺寸：列表左侧约 `44–48vp` 的圆角徽章格。
- 底色：继承所属游戏的主题色；合集成就使用鸡蛋黄、奶油金和羽毛绿等全局色。
- 构成：小游戏 Logo 作为来源识别，小型语义图标作为成就识别。
- 语义图标统一为星星、皇冠、旗帜、时钟、闪电、羽毛、鸡蛋、收藏等有限集合，优先使用 ArkUI `SymbolGlyph` 或项目内统一图形，不依赖系统 Emoji 的不同机型渲染。
- 已解锁：温暖金色高光、清晰勾选；未解锁：低饱和暖灰但保证文字可读；重要里程碑可加轻微金色光晕。
- 所有图标、描边、阴影和深浅色对比都由统一 token 控制，不在 `HubPage.ets` 中散落颜色值。

## 4. 游戏内解锁反馈

### 4.1 核心形式：顶部“鸡窝勋章”

完成成就时，不使用居中弹窗、全屏遮罩或需要点击“知道了”的对话框。默认反馈是顶部居中的非阻断成就胶囊，命名为“鸡窝勋章”。

```text
               ┌──────────────────────────┐
               │  [游戏 Logo]   新成就     │
               │  [金色徽章]   西瓜到手   │
               │              合成了西瓜   │
               └──────────────────────────┘
```

视觉规格：

- 位置在系统安全区和游戏顶部栏的下方，水平居中；不占用底部控制区、棋盘主区域或系统手势区。
- 宽度约 `240–280vp`，高度约 `64–72vp`；小屏可等比收窄，但标题最多两行，不让文案挤压控件。
- 左侧为当前游戏 Logo 与金色成就徽章，右侧为“新成就”、成就名称和一句简短事实说明。
- 默认不响应触摸，使用 `HitTestMode.None`，避免吞掉俄罗斯方块、2048、扫雷和拖拽类游戏的输入。
- 玩家需要查看详细条件时，通过大厅成就墙进入详情，而不是在通知上放点击操作。

### 4.2 动效与停留时间

通知应轻盈地表达“达成”，不抢走游戏本身的高光。

1. `180ms`：从顶部轻微下落并淡入，徽章做一次小幅缩放弹性。
2. `2.2s`：稳定展示；关键成就最多增加 2–3 枚低成本星点或羽毛粒子。
3. `220ms`：向上轻移并淡出。

动效由 `CoopMotion` token 统一管理。大面积粒子、全屏闪光、长时间缩放和每帧重建 ArkUI 节点都不进入首版，以免影响 Canvas 游戏的帧率。

### 4.3 何时展示

默认规则是“先完成游戏自身反馈，再展示成就”。成就状态可以立即写入存档，但视觉通知必须等到不会打断操作的安全时机。

| 游戏 | 成就类型 | 推荐展示时机 |
| --- | --- | --- |
| `rpsBattle` | 首局、支持阵营获胜、转化风暴 | 结果层出现并稳定约 `350ms` 后 |
| `freecell` | 通关、少步、限时 | 胜利结果层出现后 |
| `minesweeper` | 胜利、快速、插旗 | 胜利结果层出现后 |
| `chicken2048` | 256 / 1024 / 2048 | 合成动画、分数变化和棋盘状态稳定后；不得在滑动中打断 |
| `tetris` | 四消 | 消行动画完成、方块稳定后；其他结算类成就在结果层出现后 |
| `suika` | 西瓜、最终合成 | 水果合成与物理反馈完成后；普通分数类成就在结算后 |

关键原则：

- 2048、四消、合成西瓜等“高光瞬间”可以即时反馈，但一定排在原本的玩法动画之后。
- 扫雷、空当接龙、RPS 胜负等结算型成就，优先在结果层后显示。
- 不在玩家拖拽、滑动、按键、方块下落、Canvas 高速物理计算的中途强行弹出。
- 成就通知只表现已判定结果；通知被延迟、合并或清空时，存档中的解锁状态不能丢失。

### 4.4 队列、声音与结算页回看

- 同一局按队列一次显示一条；相邻通知之间留短间隔。
- 同局超过 3 条时合并为“本局解锁 3 项新成就”，具体内容留给成就墙查看，避免连续刷屏。
- 游戏进入身份胶囊 `GameEntryBadge` 显示期间，成就通知等待，确保顶部不会重叠。
- 结算页增加“本局新成就”一行或小区域。通知淡出后，玩家仍能立即确认本局得到的成就。
- 解锁音效与轻震动只在对应的全局设置真正启用时触发，且仅在首次解锁时播放；首版不额外增加新的设置项。
- 历史存档迁移补发、重复事件和调试会话都不弹通知。

## 5. 实现边界

通知必须是应用壳能力，而不是每个游戏各写一套。

```text
游戏 Page / Rules
  └─ 上报结算结果或即时里程碑事实
        └─ Index.ets
              ├─ AchievementEngine 判定并保存进度
              └─ AchievementNoticeQueue 入队
                    └─ AchievementUnlockNotice / 鸡窝勋章
```

- 在 `Index.ets` 的根 `Stack` 中条件挂载通知，复用现有 `GameEntryBadge` 的安全区、定时器清理和转场思路。
- `AchievementUnlockNotice` 仅接收已解锁成就的展示数据，不进行规则判定、不读写 `preferences`。
- `HubPage.ets` 只读成就目录与进度，不能继续硬编码某款游戏的阈值。
- 各游戏只上报真实事实；例如 2048 上报 `maxTile`，俄罗斯方块上报 `lines`、`level` 和单次消行数。

## 6. 实施顺序与验收

建议按下面顺序落地：

1. 确认本文件的成就名称、范围及尚待校准的阈值。
2. 先实现统一的成就类型、注册表、纯判定引擎和独立空状态初始化；不做旧存档成就迁移。
3. 为六款主推游戏逐个接入结算事实；先覆盖 2048、扫雷、俄罗斯方块和水果摊，再接 FreeCell 与 `rpsBattle`。
4. 重做大厅成就墙、徽章和详情页。
5. 顶部鸡窝勋章与内存队列已完成；之后每次只接入一款游戏的事实上报、真机展示时机与该游戏结算页“本局新成就”回看区。

验收重点：

- 成就解锁不阻断任何 Canvas、拖拽、按键或系统手势输入。
- 高光成就在游戏原有反馈之后出现，结算成就在结果层稳定后出现。
- 多项成就不会刷屏，重复事件不会重复解锁或再次震动 / 发声。
- 小屏、深色模式和手机画布模式下，通知、成就卡和底部 Tab 都不截断、不重叠。
- 每款游戏至少记录一次临界解锁、一次普通结算和一次重复事件的真机验证。
