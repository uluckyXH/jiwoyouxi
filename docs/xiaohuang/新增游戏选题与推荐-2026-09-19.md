# 新增游戏：确定名单与选题记录

日期：2026-09-19

状态：五子连珠首版与代码验证完成；七巧板按用户决定暂停并隐藏，保留代码与素材。用户偏好 2048、水果摊式的合成、连锁反馈与持续冲分，下一款待讨论确认。

## 此前确定的四款游戏

**后续确定制作：七巧板、管道连通、五子连珠、记忆翻牌。** 用户已补充确认，名单中的“五子棋”指的是单人彩珠排线消除的**五子连珠**。双方对弈的五子棋、黑白棋仍不添加。

| 确定游戏 | 玩法定位 | 中文工作名 | 设计重点 |
| --- | --- | --- | --- |
| 七巧板 | 观察形状、拖动旋转、拼出目标图案 | 拼一座小院 | 拼片手感、旋转翻面、吸附、合法拼法验证 |
| 管道连通 | 旋转管道，完成整张连通网络 | 庭院引水 | 清楚的连接反馈、关卡可解性、温和难度 |
| 五子连珠 | 单人彩珠寻路、排线消除、持续冲分 | 花窗连珠 | 移动路径、可达提示、补珠公平性、颜色与形状辨识 |
| 记忆翻牌 | 记住牌面位置，逐步找全配对 | 庭院寻双 | 卡面细节、翻牌节奏、快速操作与中断恢复 |

这四款加入后，合集将从当前六款扩展到十款。推箱子、贪吃蛇、滑块解围、解结、数织保留研究记录，不纳入本轮开发范围。列表按用户给出的顺序整理，后续逐款完善详细设计并实现。

我理解这次想保留的是 2048 的几个优点：规则容易理解、操作直接、每一步有清楚反馈、可以慢慢规划、愿意再开一局。新游戏可以保留这些体验，同时把玩家的主要思考换成连接、路径或空间解围。

下方玩法依据来自原作者或发行方规则；中文工作名、美术构想、局长目标和开发难度是选题阶段的设计判断，性能描述不是设备实测结果。具体落地以专属设计为准：[五子连珠 · 花窗连珠](五子连珠-花窗连珠设计与实现.md)。

## 性能选题：优先减少持续开销

现有代码提供了两个有用的参照：

- **2048**：一次操作后计算棋盘变化，播放有限时长的移动、合并等动画；没有持续运行的物理模拟。规则计算和主要动效集中在操作前后。[当前移动实现](../../entry/src/main/ets/gamesNext/glow2048/GlowPage.ets)
- **水果摊**：对局使用帧回调，活动水果需要更新运动、查找接触并求解碰撞。当前已有逐颗休眠、局部唤醒、接触对复用和静止时按需绘制，不能把以前的满筐卡顿当成当前状态；果堆运动时仍比小棋盘的一次规则计算承担更多持续工作。[帧调度](../../entry/src/main/ets/gamesNext/fruitMarket/MarketFrameClock.ets)、[物理实现](../../entry/src/main/ets/gamesNext/fruitMarket/MarketEngine.ets)、[已归档的 v4 设备反馈](合成大西瓜/水果摊性能日志.md)

据此，优先选**思考时不需要持续模拟，操作后做少量计算和短动画**的玩法。仍需分别考虑规则计算、绘制、存档与音效；静止不等于零功耗，SVG 也不自动代表低开销。

| 研究方向 | 主要计算何时发生 | 预期性能与设计取舍 |
| --- | --- | --- |
| 管道连通 | 旋转后检查接口、连接关系与完成条件 | 小棋盘预计较轻。水路用一次短动画表达接通；关卡生成、唯一解校验另外处理，不做持续流体模拟。 |
| 滑块解围 | 拖动时检查有限障碍与边界，落位后判定过关 | 普通操作预计较轻。提示求解可能搜索很多状态，要按请求运行并限制范围，不能在每次拖动中全盘求解。 |
| 五子连珠 | 移动前找通路，落位后检查排线与补珠 | 已实现轻松 7×7、经典 9×9，无持续碰撞与静止帧循环；规则和布局通过代码验证，设备功耗待实测。 |
| 七巧板 | 拖动、旋转时更新位置，落位后做几何覆盖判定 | 仅七块拼片，预计较轻；使用几何与吸附，不给拼片加入刚体碰撞。 |
| 推箱子 | 移动时检查相邻格、推箱合法性和目标点 | 普通移动预计较轻。题目提前校验；提示搜索与复杂死锁判定需要控制预算。 |
| 记忆翻牌 | 翻牌时改变状态，两张揭开后比较图案 | 预计较轻。限制同时活动的翻牌动画，配对完成后静止；快速点击时保持状态一致。 |
| 经典贪吃蛇 | 固定节奏移动一格、检查占位，渲染时表现平滑移动 | 有持续更新，但可用有界棋盘、单条蛇和简单占位规则控制负担；不能与静止解谜等同，也不需要果堆式碰撞求解。 |
| 解结 | 手指拖动节点时检查线段交叉 | 少量节点预计较轻，连线增多后检查次数和重绘都增加。首版限制规模，用几何线段，不引入绳索物理。 |
| 数织 | 填格时更新局面；提示、生成和校验时求解 | 普通填格预计较轻。题库可提前校验，避免临时生成难题阻塞操作；大棋盘也要考虑文字与网格绘制。 |

性能轻不必以牺牲手感为代价。可以继续保留 2048 那种短滑动、吸附、点亮和清楚的音效，把效果集中在用户刚完成的动作上。大面积模糊、很多透明图层、常驻粒子和背景循环动画都应克制；背景可以通过静态 SVG 的层次与细节做丰富。

持续运行的游戏也可以较轻，关键还包括每次更新的工作量、对象数量和绘制方式。贪吃蛇的简单格子规则就是可研究的方向；不会仅因有实时移动就把它与水果物理模拟归为同一档，也不承诺实际功耗与 2048 一样。

后续实现时验证静止、连续操作、提示计算和折叠重排等场景，区分持续负担与瞬时峰值。本次只完成名单定稿，不进行新的性能测试或水果摊优化。

## 管道连通：已确定制作

**玩法一句话：点击旋转管道，让整张网络接上水源。**

参考 Net 的规则：打乱各格的方向后，通过旋转把全部格子接成一个连通、没有闭环的网络；连接到源点的部分会高亮。它不是只要求起点与某一个终点相通。[Net 原作者规则](https://www.chiark.greenend.org.uk/~sgtatham/puzzles/doc/net.html)

### 为什么值得做

- 每一步只需点击，容易理解，也很适合单手操作。
- 思考重点在相邻接口与整张网络，和数字合并、排雷、牌序都有明显差别。
- 「转对一格 → 一段水路被接通 → 更多花盆得到水」能提供清楚而舒服的反馈。
- 可做精选关卡，也可做带固定种子的随机题，具有后续扩展空间。

### 我们可以怎样设计

工作名 **庭院引水**。浅色像奶油石砖上的青绿色水渠；深色像安静的夜间庭院，以柔和的亮色标示接通的水路。普通管道、分叉、源点、终端花盆各有独立 SVG 轮廓。

点击后管道短促转向，水线沿新增接通的部分展开，花盆舒展叶片；通关时做一次完整水网的短反馈。动画结束后保持静态，不让整张水网一直流动。旋转配清楚的小咔哒声，接通配短水声，声音跟随 App 开关。

首版候选范围：从 4×4 教学到 5×5 普通题，熟悉后再开放更大的棋盘；提供撤销、重新开始、固定已确认管道、一步提示和断点续玩。默认没有倒计时，不按转动次数扣生命。

**制作重点**：先构造可解网络再打乱，并检查题目难度。若提供唯一解关卡，需要求解校验；「随机拼一堆管道」不能保证题目质量。首版可先用精选题，随机题在校验可靠后再加入。

可先了解原玩法：[Net 网页版](https://www.chiark.greenend.org.uk/~sgtatham/puzzles/js/net.html)。本次只查看规则，没有把它接入 App。

## 五子连珠：已确定制作

这里指**单人彩珠排列消除**。

点击一颗棋子，再选择目标空格；两者之间需要有通路。把五颗或更多同类棋子排成横、竖或斜线即可消除。未形成消除的移动会让棋盘出现新棋子，形成消除则获得不新增棋子的机会；棋盘填满时结束。[GNOME Five or More 规则](https://help.gnome.org/five-or-more/rules.html)

### 为什么值得做

- 它保留 2048 的「这一步看着简单，但要给后几步留位置」的节奏。
- 玩家规划的是棋子的路线和排列位置；已经排好的半条线，也可能堵住另一颗棋子的路。
- 自然适合最高分和反复开局，不必靠大量手工关卡支撑。

**设计方向**：围绕寻路、可达区域和排线反馈建立独立手感，保留低持续开销。用户已明确确认制作这一单人彩珠消除玩法。

### 我们可以怎样设计

工作名 **花窗连珠**。棋子做成不同轮廓和花纹的彩色玻璃珠，颜色同时配图形标识。浅色是透亮花窗，深色是有清楚边缘的彩釉；避免只用红绿区分棋子。

选中棋子后显示可达区域，移动时沿实际空格路径滑行；排成一线后依次亮起、短暂收拢消除。预览下一批棋子的种类，让玩家有规划依据。短音符随消除响起，连续操作时合并音效，避免叠成噪声。

首版可以围绕一个适合手机的棋盘打磨；官方实现的 7×7 小棋盘可作为研究起点，其参数为五种棋子、每次补三颗。我们的入门难度仍需通过试玩决定，不能把格子少直接等同于简单。[官方棋盘参数](https://help.gnome.org/five-or-more/change-board-size.html)

**制作重点**：路径合法性、随机补珠节奏和失败后的复盘感。若提供撤销，需要恢复随机状态，保证撤销重走不会变成反复刷新下一批棋子。

## 图形、记忆与其他方向的研究记录

### 七巧板：已确定制作

用七块几何拼片拼出指定轮廓，可以是小鸡、房屋、船或其他图案；参考玩法要求使用全部七块完成目标图形。[SmartGames 七巧板玩法示例](https://smartgames.com/nl/1-speler-spellen/tangoes-starter)

工作名 **拼一座小院**。每关完成一张独立小图，通关后收入图册。采用暖木、彩釉或纸片质感的 SVG，拖动贴手、旋转短促、接近合适位置时轻吸附，完成后整幅图短暂亮起。它更侧重形状与方向的观察，和现有游戏的数字合并、消行目标不同。

**设计重点**：手机上提供清楚的旋转与翻面按钮，不强迫用户用双指操作小拼片；展开屏留出更宽的拼片托盘。几何验证接受多个合法拼法和等价拼片交换，不能只认预设的每块位置。首版用精心设计的小图，控制吸附容差与提示力度，避免自动拼完失去乐趣。

**取舍**：运行预计较轻，触控、几何判定和图案关卡是主要打磨内容；用户已将它确定为后续四款之一。

### 推箱子：本轮不纳入

控制角色把所有箱子推到目标位置。一次只能推一只箱子，不能拉回，也不能推动两只挨在一起的箱子。[Sokoban 官方规则](https://www.sokoban.jp/rule.html)

工作名 **小鸡搬家**。小鸡在庭院里把木箱搬到收纳位置，行走、推动、箱子归位分别有短动画和清楚的轻音效。可以慢慢想，不默认倒计时；支持连续撤销，让试错成为游玩的一部分。

它和滑块解围的区别在于：**角色必须能走到箱子的正确一侧**，玩家同时安排人物路线与箱子次序。箱子进了错误角落可能再也推不出来，这也是关卡深度的重要来源。

**设计重点**：首批关卡从小场景、少箱子开始，用原创且经过校验的题目。提示针对当前局面，简单死角可以及时反馈；复杂求解按需运行并限制预算。推箱子与滑块解围建议先选一款，避免连续加入两个空间腾挪关卡游戏。

### 记忆翻牌：已确定制作

每次翻开两张牌，图案相同就配成一对，不同则盖回原位；逐步找全所有配对。[Ravensburger 官方配对规则](https://www.ravensburger.us/spieleanleitungen/ecm/Spielanleitungen/20359_Anl_EN_FR.pdf)

工作名 **庭院寻双**。用我们自己绘制的小鸡、花盆、风铃、茶杯等 SVG 做卡面。翻开、配对、盖回有柔和的层次和短声音；配对成功可把图案收到页边的小图册里。单人模式默认无时间压力，记录翻牌次数，速度挑战以后再讨论。

**设计重点**：少量配对起步，用不同轮廓辅助颜色辨识。快速点击不能翻开第三张正在等待结算的牌；切后台或折叠重排时保留当前牌面和待结算状态，不能多揭牌或漏结算。

**取舍**：它补充记忆体验、上手负担低，预计计算也轻；长期策略深度较浅，更适合作为一两分钟的小休息。难度通过适量的配对数和图案辨识调整，避免只靠无限增加牌数。

### 经典贪吃蛇：本轮不纳入

控制前进方向、吃到食物并避开障碍。经典蛇类游戏可以用 GNOME Nibbles 的移动与食物规则作参考，本项目若选择它会先做单人、单条队伍的简单版本。[Nibbles 官方介绍](https://help.gnome.org/gnome-nibbles/index.html)、[食物与增长规则](https://help.gnome.org/gnome-nibbles/scores.html)

工作名 **庭院小队**。可画成小鸡带着逐渐变长的队伍收集谷粒。规则保持沿格子转向、队伍增长、避免撞墙或自身；移动用短插值表现平滑，吃到谷粒响一个轻快音符。它的重点是路线与转弯时机，即时压力会高于前三个新增方向。

**设计重点**：滑动与大圆角方向键可选，限制不合法的反向输入，缓冲快速的连续转弯；提供慢速入门。折叠、旋转、切后台时暂停并保留局面，布局稳定后由玩家继续，避免屏幕变化期间撞墙。

**性能边界**：格子逻辑不需要水果堆式连续碰撞，单条蛇、有界棋盘预计可控制开销；平滑画面仍会持续更新。首版不加入大量独立角色、拖尾粒子或物理身体，也不能仅凭规则简单就承诺所有设备的帧率与耗电。

## 滑块解围：保留的拖动关卡方向

**玩法一句话：滑开挡路的物件，让主角沿出口离开。**

可参考 Rush Hour 系列的基础思路：阻挡物沿各自朝向前后移动，玩家依次腾挪，清出目标物到出口的路线。[ThinkFun 官方规则示例](https://legacy.thinkfun.com/wp-content/uploads/2015/09/RushHJr-5041-Instructions.pdf)

工作名 **小鸡出门**。用有方向感的小木车、花箱和主角载具组成庭院棋盘，主角朝着门口移动。物件长度与朝向必须一眼可读，美术不能遮住实际占格。

它的满足感来自「先挪开这块，另一块终于能动了」，重点是空间阻塞关系；和 2048 的全盘滑动、接龙的牌序整理均有区别。可以做短关卡，让第一次通关比最少步数更重要。

视觉上重点做贴手拖动、松手吸附、碰到边界的轻反馈、出口打开与主角离场。浅色用暖木与草地，深色用暗木和门边暖灯。关卡、文案、SVG 与音效单独设计。

**制作重点**：关卡需要能逐步教学，不能随意摆放障碍。一步提示要针对玩家当前局面计算；有多种合法解法时都应接受。相比五子连珠，它更依赖持续制作和校验好关卡。

## 解结：最直观的拖动解压选择

原玩法给出一些由线连接的点，玩家拖动这些点，让连线之间不再交叉。[Untangle 原作者规则](https://www.chiark.greenend.org.uk/~sgtatham/puzzles/doc/untangle.html)

工作名 **风铃解结**。节点做成小木珠、叶片或铃坠，连线有清晰的前后关系；拖动后减少的交叉会柔和退色，完成时响一次风铃。

这款的优势是没有复杂文字说明，操作反馈非常直观，也适合展开屏。短板是长期目标感较弱，单纯增加点数容易变成一团难以辨认的线。

首版应保持少量、足够大的节点，优先设计能看懂的布局。实现上采用节点与直线的交叉判定，重点控制拖动时的检查和重绘范围。它可以作为后续的轻松小品，暂不优先于管道连通和滑块解围。

## 数织：适合喜欢慢慢完成一幅画的玩家

根据每行、每列的数字，推断连续填色格的长度与间隔，逐步还原整张图案。这与扫雷周围八格的数字含义不同。[Pattern / Nonograms 原作者说明](https://www.chiark.greenend.org.uk/~sgtatham/puzzles/doc/pattern.html)

工作名 **像素小院**。完成后呈现小鸡、花盆、茶杯、房屋等小图，形成图册。界面和按钮使用 SVG，棋盘保持清楚的网格与行列线索。

推荐作为偏安静的解谜补充。它比 2048 更依赖阅读线索，手机还需要给外侧数字留空间。若选择这个方向，应先做小图与优质题库，验证每题能用逻辑解决，再扩充题量。图案可爱不等于线索一定好解。

## 四款共同的设计与实现要求

- **独立实现**：在新的游戏目录中编写原生版本，保留现有六款和旧版游戏代码。每款完成后接入首页，入口与游戏内使用同一套 Logo。
- **App 主题**：延续现有暖色、圆角和清晰层级；浅深色分别设计背景、棋盘、选中态和错误态。场景、Logo、按钮、图标直接画 SVG，动态文字用原生组件。
- **自主设计**：每款重新设计场景、背景细节、按钮和图标，以 App 主题与用户要求为依据；前期工作名、构图和文档草案不限制后续美术创作。游戏内不出现“重构中”等开发状态文案。
- **反馈**：操作先有明确结果，再配 2048 那样顺滑的短动画；音效清楚可辨、音量足够，跟随 App 声音开关并控制连续叠音。思考时保持安静，避免装饰持续漂浮。玩法指南配简单演示，说明基础规则与辅助功能。
- **手机与折叠外屏**：优先大而清楚的主操作区；提示、撤销等辅助按钮靠近棋盘，但不挤占触控空间。
- **展开屏与平板**：棋盘适度放大，额外空间安排关卡、提示或记录；不会只把手机版等比拉长。
- **半折叠、分屏与旋转**：按实际可用区域重排；对局、撤销记录和当前选择保持。空间确实不足时可以浏览棋盘，不用姿态限制代替布局设计。
- **存档与性能**：支持离线与中断恢复。优先输入驱动的规则与有限时长的动效；拖动检查、关卡生成、提示求解分别控制规模与执行时机。实时玩法控制每次更新工作量，暂停时停止更新；折叠后也不遗留旧动画或重复计时器。本轮没有原型或性能实测。
- **成就**：每款接入现有的首次达成、保存、去重与提醒机制，设计容易理解和达成的目标，并绘制对应 SVG 勋章。同步游戏来源白名单和分组，以代码验证实际事件可触发；「六边形鸡仔」保持原六款的门槛，已有勋章不撤回。现有提醒样式保持。

## 后续推进

本段保留此前推进思路。最新调整以文首状态为准：七巧板暂停，下一款重新讨论。

1. 每款先补齐玩法、难度与关卡或随机规则、SVG 场景与图标、手机与大屏布局、动效音效和成就的详细设计。
2. 新建独立游戏目录实现原生版本，结合规则特点处理输入、撤销或辅助功能、存档与折叠重排。

最初选题阶段仅记录名单；后续实现与隐藏状态见文首及各游戏独立文档。
