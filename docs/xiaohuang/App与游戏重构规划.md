# App 与游戏重构规划

记录日期：2026-09-18

状态：整体重构计划；2026-09-18 已开始首个游戏「鸡窝水果摊」的独立新版实现，其他 App 全局改造仍在后续计划中。

当前进度见 [水果摊独立重构版](合成大西瓜/水果摊独立重构版.md)。以下保留最初确定的整体方向，具体实施进度以上述文档为准。

## 一、这次要解决什么

当前 App 与游戏之间的主题衔接、页面布局和交互风格不够统一，游戏对平板、折叠屏等设备的适配也不理想。本次准备从整体体验出发重新设计，范围包括 App UI、开屏动画，以及独立重写的新版游戏。

现有 `entry/src/main/ets/design/CoopViewport.ets` 主要在较大的窗口中保持手机画布尺寸。这能维持手机布局，但不能代替大屏上的信息重排、操作区布局和折叠状态适配。后续应根据可用窗口空间设计，而不是只把手机画面居中或整体放大。

这份文档中的「已确定」来自本次需求；目录命名、实施顺序和视觉方向属于初步建议，可在开始实施时调整。

## 二、已确定的重构边界

| 范围 | 处理方式 |
| --- | --- |
| App 非游戏 UI | 可以直接修改现有实现，重新统一首页、导航、收藏、成就、设置及公共弹窗等体验。 |
| 开屏与 App 动画 | 纳入重新设计，包括启动到首页的衔接，以及页面切换和交互反馈。 |
| 现有游戏 | 保留现有游戏代码，不在原实现上进行这次重构。 |
| 新版游戏 | 在一套新的独立目录中重写，与旧版并存。 |
| 首页入口 | 新旧版可以使用相同的游戏名称和图标；新版入口必须明确标注「重构中」。 |
| 适配目标 | 统一 App 与新版游戏的主题体验，覆盖手机、平板和折叠屏。 |
| 初始记录阶段 | 先记录未来工作；首个游戏已于后续指令中启动，详见上方进度链接。 |

旧游戏应继续可以进入和游玩。App 公共层发生变化时，也需要保留旧游戏依赖的接口和运行行为，避免通过修改共享组件、主题或资源间接影响旧版。

## 三、角色与整体视觉的初步方向

本轮角色 SVG 是素材探索稿，尚未作为最终角色方案确认。参考图的表现力来自柔和的三维体积、材质和光照；当前 SVG 的头部渐变、身体轮廓与格纹密度不够一致，整体显得不协调。

建议先确定角色的比例、表情、服装细节和材质表现，再决定使用哪种资源形式。角色可以采用插画或渲染素材；图标、按钮、标识和简单装饰仍适合 SVG。格式服务于画面效果，不作为统一风格的唯一手段。

后续视觉探索重点：

- 让角色、海报、游戏入口和游戏场景属于同一套视觉语言。
- 统一色彩、字号层级、间距、圆角、边框、阴影与动效节奏。
- 浅色和深色模式分别设计层次与对比度，避免简单反色或一层灰色遮罩。
- 同时看手机与大屏效果，避免先定手机稿，再被动拉伸。

现有角色探索资源先保留，是否继续使用、简化或重新绘制，在视觉方案阶段决定。

## 四、新旧游戏并存方案（建议）

建议将新版实现集中放入 `gamesNext`，名称在实施时可以调整：

```text
entry/src/main/ets/
  games/                       现有游戏，保留原实现
  gamesNext/                   新版游戏独立实现
    shared/                    新版共用的布局、主题与交互组件
    <gameId>/                  各游戏的页面、规则、状态与表现

entry/src/main/resources/rawfile/
  gamesNext/                   新版游戏资源，避免覆盖旧版资源
    <gameId>/
```

App 导航、首页和游戏注册层负责接入两套入口。新版使用独立的内部 ID 或版本标识，显示名称和图标可以沿用原游戏。例如首页同时出现「扫雷」和带「重构中」标记的「扫雷」，点击后分别进入对应版本。

「重构中」标记应在卡片上直接可见，不能只依赖颜色区分。只有具备可体验内容后才将新版入口接入首页；尚未完成的功能应清楚说明。

新版的局内存档先与旧版隔离，避免覆盖现有进度。收藏、最近游玩、最高分和成就需要明确如何识别版本：默认不重置旧数据，也不因为多了一个版本就将同一款游戏重复计入游戏总数。具体继承和迁移方式在接入首个新版游戏时设计。

## 五、App、开屏与设备适配方向（建议）

### App UI

先建立统一的视觉与交互基础，再落实到首页、收藏、成就、设置等页面。首页同时承担内容展示、继续游玩和新版入口识别，不只替换图标和背景。

### 开屏与动画

分别处理系统启动窗口和 App 内开场动画，让启动图标、背景、角色表现与首页自然衔接。开场应短而有辨识度，避免为播放动画延迟进入可操作界面；从后台返回时无需重复完整开场。具体分镜、时长和实现方式留到设计阶段确认。

页面切换、进入与离开游戏、按钮反馈和结算动画应有统一节奏。旧游戏的内部动画保留；新版游戏随新实现设计。

### 手机、平板与折叠屏

- 按实际可用窗口宽高安排布局，覆盖横竖屏、分屏和窗口大小变化。
- 手机优先保证主操作区、文字与触控目标的可用性。
- 平板利用额外空间安排棋盘、状态、说明或操作区，而不只是放大留白。
- 折叠屏考虑折叠前后、不同窗口比例和遮挡区域；需要避开折痕或铰链的位置应按设备能力处理。
- 新版游戏在窗口变化和折叠切换时保留当前对局，不因为重排布局而重新开局。
- 浅深色主题、系统安全区与触控反馈应在上述形态下保持一致。

这些是 App 与新版游戏的重构目标，旧游戏暂时继续使用各自现有布局。

## 六、建议实施顺序

1. **整体视觉探索**：做首页、一个游戏页面及开屏分镜，同时比较手机、平板和折叠屏布局，确认角色表现形式。
2. **App 基础与 UI 改造**：建立主题、布局与公共组件，更新首页和其他非游戏页面，打通启动到首页的体验。
3. **首个新版游戏试点**：建立独立目录、版本入口和数据隔离，完整重写一款游戏，验证新设计是否适合实际游玩。首款已确定为「鸡窝水果摊」，独立新版已接入首页。
4. **扩展其他游戏**：复用已经验证的新版基础，逐款重写并在首页标注「重构中」。
5. **统一验收与后续切换**：检查设备适配、主题、动效、数据和游玩流程；新版稳定后的默认入口调整与旧版去留另行决定，不在重构过程中自动删除旧游戏。

## 七、后续验收重点

- 首页可以清楚区分新旧版本，两个入口都进入正确实现。
- 旧游戏代码保持原样，进入、返回和原有数据不受 App 改造影响。
- 新版游戏的完整对局、暂停、重开、结算和存档流程可用。
- 手机、平板、折叠屏及窗口变化时没有内容遮挡、异常拉伸或不可触达的操作；新版对局状态能够保持。
- 浅深色主题下，App 与新版游戏的文字、图标、弹窗和交互状态保持清晰统一。
- 冷启动、后台返回和页面切换连贯，开场动画不妨碍操作。

实际实施时记录已验证的设备与窗口场景，未验证项单独列出。本文件描述整体计划，具体完成范围以各阶段实施记录为准。
