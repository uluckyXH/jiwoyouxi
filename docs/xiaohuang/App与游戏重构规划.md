# App 与游戏重构规划

记录日期：2026-09-18

状态：整体重构计划；2026-09-18 已开始首个游戏「鸡窝水果摊」的独立新版实现，由另一位 Codex Agent 继续负责。本轮指定的「扫雷」独立新版已完成并接入首页，已通过构建、规则测试和手机／平板／折叠屏模拟器验证；真机音量、折痕与长时间游玩仍待验收。

水果摊实施进度见 [水果摊独立重构版](合成大西瓜/水果摊独立重构版.md)。本规划已按 2026-09-18 最新确认更新；历史设计或实施记录与本次要求冲突时，以最新用户要求为准。

扫雷本轮成果见 [扫雷独立重构版](扫雷/扫雷独立重构版.md) 与 [扫雷测试报告](../../测试报告/2026-09-18-扫雷独立新版.md)。新版采用「庭院探雷」设计，恢复三档难度，独立绘制 SVG 并加入本地音效；经典版代码、资源和入口保留。

## 一、这次要解决什么

当前 App 与游戏之间的主题衔接、页面布局和交互风格不够统一，游戏对平板、折叠屏等设备的适配也不理想。整体长期规划包括 App UI、开屏动画和独立重写的新版游戏；当前其他游戏的重构要求是：以现有 App 原版 UI 的风格与浅深色主题为衔接基础，重新设计游戏场景、Logo、按钮和整体界面，并适配手机、平板和折叠屏。不以重做整个 App 为游戏重构的前提。

现有 `entry/src/main/ets/design/CoopViewport.ets` 主要在较大的窗口中保持手机画布尺寸。这能维持手机布局，但不能代替大屏上的信息重排、操作区布局和折叠状态适配。后续应根据可用窗口空间设计，而不是只把手机画面居中或整体放大。

这份文档中的「已确定」来自用户需求。具体视觉方案由设计与实现者自主设计，不受旧项目文档中的场景、布局或素材方案束缚；旧文档与旧版游戏用于了解玩法和参考实现。下文明确的主题、SVG、设备适配、新旧版保留等要求是执行与验收依据，具体构图和实现方案可调整。

## 二、已确定的重构边界

| 范围 | 处理方式 |
| --- | --- |
| App 非游戏 UI | 当前以现有 App 原版 UI 为风格与主题衔接基础；重构游戏时按需接入首页、路由和统一 Logo。首页、导航、收藏、成就、设置的整体改造仍属于后续规划。 |
| 开屏与 App 动画 | 保留为整体长期规划；本次确认其他游戏的要求，不自动启动 App 开屏与全局动画改造。 |
| 现有游戏 | 保留现有游戏代码和资源，不删除、不在原实现上重构，继续可玩并可供参考。 |
| 新版游戏 | 在 `gamesNext/<gameId>/` 独立目录中重写，资源也独立存放，与旧版并存。 |
| 游戏视觉 | 场景、Logo、按钮、布局、状态区和弹窗全部重新设计，注重整体 UI 与图标细节。 |
| SVG 素材 | Logo、UI 图标、按钮图形、标识及场景中的矢量装饰直接绘制 SVG；文字与交互使用原生组件。 |
| 首页入口 | 新旧版分别保留可点击入口；同一款游戏的两个入口统一使用重新设计的同一套 Logo。 |
| 游戏内文案 | 游戏标题、进入提示、玩法界面、帮助、暂停与结算弹窗中均不出现「重构中」等开发状态文案。 |
| 适配目标 | 新版游戏融合现有 App UI，完整支持浅色、深色主题，适配手机、平板和折叠屏。 |
| 协作与启动边界 | 水果摊由另一位 Agent 继续负责；本轮已指定扫雷并授权开始，其他游戏暂不启动。 |

旧游戏应继续可以进入和游玩。App 公共层发生变化时，也需要保留旧游戏依赖的接口和运行行为，避免通过修改共享组件、主题或资源间接影响旧版。

### 本轮扫雷范围（已授权）

- 新建 `entry/src/main/ets/gamesNext/minesweeper/` 和对应 `rawfile/gamesNext/minesweeper/`，保留旧版 `games/minesweeper/` 及其资源。
- 重新设计扫雷场景、SVG Logo、图标、按钮、棋盘、难度选择、状态信息和弹窗；首页新旧入口共用新版 Logo。
- 恢复可调整的难度。棋盘按规则与行列数生成，不再由固定整张素材限制棋盘尺寸；大棋盘需保持可触达的格子尺寸并支持浏览。
- 增加适合扫雷的交互细节与本地音效，包括翻格、插旗、连开、胜负反馈；声音与 App 开关联动。
- 保留首点安全，考虑长按插旗、数字周围快速展开、暂停与返回、对局恢复等完整流程；新增玩法不以牺牲公平性或可用性为代价。
- 完整适配 App 浅深色主题、手机、平板、折叠屏与窗口变化，重排时保留对局。
- 后续扫雷体验优化：手机随难度缩小棋盘，优先完整显示并消除横向拖动；平板和展开的折叠／三折叠大屏保留现有格子大小。提高局内音效清晰度，并用实际基准评估性能，避免无依据地重写轻量规则。
- 扫雷半折叠及空间不足时按用户最终确认允许上下左右滚动；不因空间不足遮蔽棋盘、禁止继续或要求切换设备姿态。
- 扫雷手机高难度收紧控件和卡片留白，把高度让给棋盘；背景 SVG 按边角独立定位，展开／收起／旋转加入短布局过渡。此次追加调整由用户自行查看页面，Agent 完成代码、构建检查后仅提交并推送扫雷部分。
- 改好规划后直接实施，无需另行等待开工确认。成果与验证记录另写扫雷实施说明及测试报告。

## 三、UI、SVG 与视觉设计要求

### 已确定的设计要求

- 游戏场景、Logo、按钮和整体界面重新设计，不直接照搬旧版，也不因旧设计文档限制新的视觉方案。
- 以现有 App 的暖色、圆润和浅深色主题为衔接基础，让游戏具有自己的辨识度，同时与首页、进入提示和公共反馈保持协调。
- Logo、UI 图标、按钮图形、标识和场景中的矢量装饰直接绘制 SVG，不用随意的字符、Emoji 或占位图代替正式图标。旧版素材保留，新版资源独立存放。
- 重点打磨图标的轮廓、线条粗细、比例、圆角、视觉居中、留白和小尺寸辨识度；同一套图标保持一致的视觉重量与细节语言。
- 按钮需同时设计图形、图标与文字的排布、尺寸、触控范围及按压反馈；适用时明确选中、禁用等状态，避免状态变化导致布局跳动。
- 浅色与深色分别设计场景、控件、文字、边框和弹窗的颜色、层次与对比度，不采用简单反色或统一遮灰。游戏接入 App 当前外观状态，不另设与 App 脱节的主题。
- 同时考虑手机、平板与折叠屏上的信息层级、操作位置和装饰密度，不能只放大手机界面。
- SVG 负责图形素材；可变文字、计分、按钮点击和无障碍描述继续使用原生组件，保证清晰与可操作。

### 角色素材的历史探索

本轮角色 SVG 是素材探索稿，尚未作为最终角色方案确认。参考图的表现力来自柔和的三维体积、材质和光照；当前 SVG 的头部渐变、身体轮廓与格纹密度不够一致，整体显得不协调。

角色探索先确定比例、表情、服装细节和材质表现，再决定角色本身的资源形式。角色可以采用插画或渲染素材；这不改变上方关于 Logo、UI 图标、按钮图形和矢量装饰直接绘制 SVG 的要求。

后续视觉探索重点：

- 让角色、海报、游戏入口和游戏场景属于同一套视觉语言。
- 统一色彩、字号层级、间距、圆角、边框、阴影与动效节奏。
- 浅色和深色模式分别设计层次与对比度，避免简单反色或一层灰色遮罩。
- 同时看手机与大屏效果，避免先定手机稿，再被动拉伸。

现有角色探索资源先保留，是否继续使用、简化或重新绘制，在视觉方案阶段决定。

## 四、新旧游戏并存方案

新版沿用已建立的 `gamesNext` 独立目录，各游戏单独组织代码与资源：

```text
entry/src/main/ets/
  games/                       现有游戏，保留原实现
  gamesNext/                   新版游戏独立实现
    shared/                    新版共用的布局、主题与交互组件
    <gameId>/                  各游戏的页面、规则、状态与表现

entry/src/main/resources/rawfile/
  gamesNext/                   新版游戏资源，避免覆盖旧版资源
    <gameId>/
```

App 导航、首页和游戏注册层负责接入两套入口。新版使用独立的内部 ID 或版本标识，同一款游戏的新旧入口使用相同的游戏名称与重新设计的同一套 Logo；首页、收藏与进入提示通过统一的 Logo 映射保持一致。可用「新版／经典版」等入口文案区分版本，点击分别进入对应实现。调整入口 Logo 时保留旧素材文件，不覆盖旧游戏内部使用的资源。

不再要求新版入口必须标注「重构中」。游戏内的标题、进入提示、玩法界面、帮助、暂停和结算均不得出现「重构中」等开发状态文案。只有具备可体验内容后才将新版入口接入首页；实施进度和未完成项记录在开发文档与测试报告中。

新版的局内存档先与旧版隔离，避免覆盖现有进度。收藏、最近游玩、最高分和成就需要明确如何识别版本：默认不重置旧数据，也不因为多了一个版本就将同一款游戏重复计入游戏总数。具体继承和迁移方式在接入首个新版游戏时设计。

## 五、App 衔接、开屏规划与设备适配

### App UI

当前游戏重构优先融合现有 App 原版 UI，接入现有浅深色外观状态，统一入口 Logo、文字层级与交互反馈。新版游戏内部的场景、控件和弹窗重新设计，并与 App 保持协调。后续若开展 App 整体改造，再将统一的视觉与交互基础落实到首页、收藏、成就、设置等页面。

### 开屏与动画

以下开屏内容保留为后续整体规划：分别处理系统启动窗口和 App 内开场动画，让启动图标、背景、角色表现与首页自然衔接。开场应短而有辨识度，避免为播放动画延迟进入可操作界面；从后台返回时无需重复完整开场。具体分镜、时长和实现方式留到设计阶段确认。

页面切换、进入与离开游戏、按钮反馈和结算动画应有统一节奏。旧游戏的内部动画保留；新版游戏随新实现设计。

### 手机、平板与折叠屏

- 按实际可用窗口宽高安排布局，覆盖横竖屏、分屏和窗口大小变化。
- 手机优先保证主操作区、文字与触控目标的可用性。
- 平板利用额外空间安排棋盘、状态、说明或操作区，而不只是放大留白。
- 折叠屏考虑折叠前后、不同窗口比例和遮挡区域；需要避开折痕或铰链的位置应按设备能力处理。
- 新版游戏在窗口变化和折叠切换时保留当前对局，不因为重排布局而重新开局。
- 浅深色主题、系统安全区与触控反馈应在上述形态下保持一致。

以上设备适配是新版游戏的明确要求，不是可选优化；旧游戏暂时继续使用各自现有布局。App 本身的全局布局改造仍按后续范围推进。

## 六、建议实施顺序

以下为整体长期路线，不表示本轮立即启动 App 全局改造。当前已指定扫雷，在独立目录实施并优先融合现有 App UI；其他未指定游戏暂不启动。水果摊继续由原负责 Agent 推进。

1. **整体视觉探索**：做首页、一个游戏页面及开屏分镜，同时比较手机、平板和折叠屏布局，确认角色表现形式。
2. **App 基础与 UI 改造**：建立主题、布局与公共组件，更新首页和其他非游戏页面，打通启动到首页的体验。
3. **首个新版游戏试点**：建立独立目录、版本入口和数据隔离，完整重写一款游戏，验证新设计是否适合实际游玩。首款已确定为「鸡窝水果摊」，独立新版已接入首页。
4. **扩展其他游戏**：按用户指定逐款重写，独立设计场景、SVG Logo、图标与按钮；融合当前 App 的浅深色主题，适配手机、平板和折叠屏，并在首页保留新旧入口及一致的 Logo。
5. **统一验收与后续切换**：检查设备适配、主题、动效、数据和游玩流程；新版稳定后的默认入口调整与旧版去留另行决定，不在重构过程中自动删除旧游戏。

## 七、后续验收重点

- 首页可以清楚区分新旧版本，两个入口都进入正确实现，并使用同一套重新设计的 Logo；收藏与进入提示也保持一致。
- 旧游戏代码保持原样，进入、返回和原有数据不受 App 改造影响。
- 新版代码与资源位于独立目录，旧版代码与素材没有删除或覆盖；水果摊的并行工作不被其他游戏重构干扰。
- 场景、Logo、按钮和整体界面完成重新设计；Logo、UI 图标、按钮图形与矢量装饰使用直接绘制的 SVG。
- 图标线条、比例、圆角、视觉居中、留白和小尺寸辨识度协调；按钮的文字排布、触控范围、按压及适用的选中、禁用状态完整。
- 游戏内标题、进入提示、玩法界面、帮助、暂停和结算中不出现「重构中」等开发状态文案。
- 新版游戏的完整对局、暂停、重开、结算和存档流程可用。
- 手机、平板、折叠屏及窗口变化时没有内容遮挡、异常拉伸或不可触达的操作；新版对局状态能够保持。
- 浅深色主题下，新版游戏跟随 App 外观状态，场景、文字、图标、按钮、弹窗和交互状态保持清晰统一，与现有 App UI 协调。
- 冷启动、后台返回和页面切换连贯，开场动画不妨碍操作。

实际实施时记录已验证的设备与窗口场景，未验证项单独列出。本文件描述整体计划，具体完成范围以各阶段实施记录为准。
