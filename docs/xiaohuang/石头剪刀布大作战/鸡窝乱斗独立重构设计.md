### 2.1 已确认的不足与待验证问题

| 观察 | 依据与影响 | 新版处理 |
| --- | --- | --- |
| 主题与 App 脱节 | 页面没有接收 App 的深浅色或声音开关；颜色来自固定浅色常量 | 统一接收解析后的主题、静音状态；Canvas 与原生 UI 同步更新 |
| 大屏只是窄界面居中 | 配置与战场宽度上限 430；战场高度随屏幕变化，缺少大屏信息重排 | 战场与操作侧栏组合布局，大小屏分别组织信息 |
| 小窗口与折叠缺少完整处理 | 页面将测量值强制抬到至少 280×420；顶部使用固定 34/88 高度，未见独立折痕与窗口生命周期适配 | 使用真实可用区域、安全区和可用面板，不以虚构尺寸掩盖溢出 |
| 旋转可能改变对局条件 | `resize()` 分别缩放实体 x/y，世界随画布比例变化，而单位半径等参数固定 | 固定逻辑世界，仅改变等比显示和触点映射 |
| 配置先于理解 | 开局连续展示模式、机制、强化、主题、支持阵营、规模、时长 | 默认提供可直接玩的方案，进阶配置折叠收纳 |
| 操作容易误放 | 干预由 `TouchType.Down` 直接释放，无选点预览与确认；顶部“重开”直接启动新局 | 技能准备态、预览、松手确认、取消；重开明确确认 |
| 内容多，但目标不够聚焦 | 占点默认包含多种机制；死斗与统一的时长选项含义不同 | 每局一个主目标，开局明确“如何赢”，事件作为有预告的变化 |
| 成绩含义不一致 | 当前分数是胜者剩余人数，受起始人数影响；开了干预便不记录正式成绩/成就 | 分开记录观战、指挥和挑战成绩，定义正式玩法边界 |
| 恢复与系统返回需补齐 | 有页面离开清理，但未见该游戏的局内持久化、窗口后台监听与独立系统返回请求接入 | 同一状态机处理暂停、后台、返回、折叠与恢复 |
| 性能仍有待实测的热点 | 寻敌仍逐单位扫描目标阵营，部分渐变逐帧创建；已有碰撞优化应保留其经验 | 先做分段测量，验证寻敌、绘制和机制成本，不能直接宣称重写就更快 |

判断：现有游戏不是缺少机制，而是缺少清楚的选择、有效的操作反馈和可理解的战局目标。新版需要把这些机制变成好玩的过程，再增加挑战内容，避免继续堆配置开关。

## 3. 视觉方向：庭院里的三支小队

场景是鸡窝旁的庭院擂台：暖色地面、低矮围栏、少量叶片和场边计分牌。主体清晰，装饰集中在战场外缘和留白处，参考水果摊的亲和感，不复刻水果摊棚顶，也不堆满木框、挂件和背景纹样。

### 3.1 阵营身份

| 逻辑身份 | SVG 形象 | 识别重点 |
| --- | --- | --- |
| 石头 | 圆润小岩团，少量切面与表情 | 石块轮廓、蓝灰色、小石纹 |
| 剪刀 | 带叶形手柄的圆头园艺剪刀 | 明确剪刀轮廓、珊瑚橙色、交叉双刃 |
| 布 | 折角方巾，轻微褶线与表情 | 方巾轮廓、草绿色、角落缝线 |

正式文字仍显示“石头 / 剪刀 / 布”，不要让玩家额外记住三套代号。颜色、轮廓、标识三重区分，深色下保持阵营身份一致。循环规则始终是石头克剪刀、剪刀克布、布克石头。

国家队、国旗不进入新资源与配置。首发也收起颜色球、品牌战等多皮肤选择，集中打磨一套有辨识度的角色；以后加外观只能改变表现，不能暗改克制关系。旧游戏原素材保留。

场景、阵营、技能、帮助图示与状态图标直接绘制 SVG。按钮文字、比分、倒计时与可访问名称用原生组件。移动单位在统一 Canvas 上绘制，不创建几十个随位置更新的 ArkUI 组件。

### 3.2 浅深色与控件

- 浅色沿用 App 奶油底色、暖白卡片、深棕文字和绿色主按钮；深色使用炭灰底、暖灰卡片、浅暖文字，保留阵营色。
- 战场地面单独调色，确保所有阵营、选点圈、护盾和危险提示可区分；不能用整体灰罩处理深色或禁用态。
- 标题区用返回、标题、声音和暂停；去掉一直露出的危险“重开”操作，放入暂停面板。
- 主要按钮圆角约 20–24 vp；普通图标视觉尺寸 20–24 vp，命中区域至少 44×44 vp。平板主操作高度 56–64 vp，不能把小按钮孤零零放在远处。
- 静态背景覆盖整个窗口，边缘渐回 App 底色；装饰分件定位，避免局部 SVG 的矩形边界出现在底部手势区。
- 字号增大时先收起装饰和次要说明；核心目标、阵营身份、暂停和技能状态保持可读，说明和战报允许滚动。

## 4. 玩法入口：三种目的，少量选择

进入游戏先看到庭院小场景、三方克制图与三张简洁玩法卡。默认选中“快速乱斗”，选择支持阵营后即可开局。规模、地图和事件放在“调整本局”中，不要求逐项配置。

| 入口 | 玩家想做什么 | 核心内容 | 默认首轮参数 |
| --- | --- | --- | --- |
| 快速乱斗 | 选一队，轻松看一场翻盘 | 三方自动追逐与转阵，保留观战乐趣 | 8/8/8，60 秒，无额外事件 |
| 据点争夺 | 亲自指挥，争夺场上主动权 | 圈内人数优势、占点进度、有限技能、公开援军 | 8/8/8，90 秒，先到 100 分 |
| 挑战小局 | 有目标地过关与重试 | 固定地图、种子、任务与技能预算，星级评价 | 首批 8 关，单关约 45–90 秒 |

“自由试验”作为调整页的进阶项，承接不对称人数、旧趣味机制与特殊组合；不作为默认开局流程，也不冒充标准成绩。三种主玩法逐步完成，每完成一种才展示对应可玩入口，不放占位按钮。

## 5. 核心规则与玩法深化

### 5.1 共同规则

- 单位自动追逐克制目标，遇到克制自己的单位会躲避，同阵营轻量分离，减少完全重叠。
- 克制接触触发转阵，保留位置与运动连续性。新增约 0.6 秒转阵保护，配细描边，避免刚变阵便在同一团中连续翻转。
- 每个逻辑步收集并稳定排序接触结果；一个单位单步最多转阵一次，固定冲突裁决顺序，避免数组遍历顺序偏袒某阵营。
- 不加入血条、装备成长或数值养成；三方基础能力对称，趣味来自位置、克制、目标和决策。
- 开局阵容、事件计划、技能预算在本局开始前确定。标准局不在中途偷偷修改阵营强弱或人数以“制造翻盘”。

### 5.2 快速乱斗：保留轻松观战，解释战局

- 只剩一方时获胜；60 秒结束时人数唯一领先者获胜，并列则平局。玩家支持阵营消失后可继续观看，也可从暂停中结束本局；主动退出不算完成。
- 默认纯观战，不出现无效技能按钮。点击阵营统计只显示克制与当前人数说明，不改变战局。
- 只保留一条短战况提示，例如“布队反超”“剪刀只剩 2 个”，节流显示，不连续弹窗。
- 结算先显示“你支持的石头队获胜 / 本局由布队获胜 / 平局”，再展示最终人数、转阵次数和一条可解释的转折。
- “再来一局”默认生成新种子；挑战的“再挑战一次”保留固定种子和规则；纯观战的原种子复盘作为后续扩展，本版不额外堆叠重玩按钮。

### 5.3 据点争夺：作为新版主要策略玩法

目标不再由“剩余人数”隐性替代。场上只有一个主据点，默认半径为逻辑边长约 14%；单位圆心进入据点计入压力。

1. 唯一人数领先的阵营持续保持 1 秒后取得控制；争夺中显示各方压力，原拥有者可以保留视觉标记，但无人或人数并列时不涨分。
2. 控制期间每秒得分建议 `2 + min(圈内人数 - 1, 3) × 0.5`，上限 3.5 分/秒。人数仍有用，但不会因大量单位挤圈瞬间结束比赛。
3. 先达到 100 分获胜；90 秒到时比较据点分，并列则平局，不再用存活数悄悄打破平局。
4. 双方电脑也使用同一套技能与冷却，依据可见战况决策，不读取未来随机结果；所有阵营指令有可见标记。入门挑战可使用较慢的电脑决策频率，并在关卡卡片标明。
5. 为维持三方循环，低于 3 个单位且持续 4 秒的阵营获得公开援军预告；2 秒后从其出生区补到 3 个，每队每局最多 2 次。出生点避开危险、受人数上限约束，援军有短保护，局内显示剩余次数。首轮不默认附加随机分裂。
6. 如果局内还有援军预告或额度，不按清场提前结算。额度耗尽后，最后一支存活队仍按占点目标获胜；三方同时归零则平局，避免空场无限等待。

上述目标、控制延时、分速和援军规则均需要批量模拟验证。重点观察：是否一边倒、技能是否真能改变占点、单局是否经常拖满、三阵营是否有先天胜率偏差。

### 5.4 有限指挥：操作明确，不靠拼点击频率

首发只提供三种技能；平时自动战斗，无摇杆、无逐单位选中要求。

| 技能 | 行为与限制 | 初始调参值 |
| --- | --- | --- |
| 集结 | 给己方附近最多 6 个单位一个优先行进目标；仍保留避敌行为，不是瞬移或强制撞向天敌 | 持续 4 秒，冷却 10 秒；目标选择范围半径为世界边长 22% |
| 护阵 | 目标圈内最多 4 个己方单位获得一次接触转阵抵挡；不叠层，不抵消已经发生的转阵或脚本叛变 | 存续 3 秒，冷却 16 秒，圈半径为边长 12% |
| 风推 | 将目标圈内各方单位向外推开，公开影响所有阵营；固定短脉冲，不能直接加分或转换阵营 | 每局 2 次，间隔至少 12 秒，圈半径为边长 16% |

集结目标超过人数上限时按到落点的距离、实体 ID 依次选择；护阵同理。同类效果不叠加放大。风推遇围栏和障碍正常阻挡，不能把单位推出世界。首局教学明确风推也会影响己方。

输入流程：

1. 点击技能进入准备态，显示作用范围和“点选位置，松手释放”。
2. 手指按下战场只显示预览，拖动可调整；松手且位置合法才消耗次数或启动冷却。
3. 松手落在战场外、收到触摸取消、按“取消”、再次点选当前技能或系统返回，均取消选点且不消耗。未选技能时点战场不释放任何能力。
4. 以首个有效触点为主指针，忽略额外手指；原生按钮区域不向战场穿透。折叠、重排、后台、暂停或主题面板打开时取消选点。
5. 有效释放给出短音效、选点圈收束与可见反馈；没有可作用单位时不扣次数，文字说明“这里没有可集结的队友”等具体原因。
6. 为辅助操作提供“投向据点 / 投向队伍”快捷目标；后者找己方最密集的一团，不要求用户精准点击移动的小单位。空范围不扣次数，并保留可见解释。

### 5.5 挑战小局：用任务让玩家学习与重玩

关卡配置包含固定种子、起始阵容、地图、基础模式、唯一主目标、失败条件、时间、允许技能和额外星级条件。关卡胜负由任务判定统一裁决，不能同时被另一个模式的默认结算抢先结束。

| 关卡 | 核心变化 | 主目标示例 |
| --- | --- | --- |
| 1. 第一声集合 | 单据点、仅集结，低频电脑指令 | 90 秒内率先达到 60 据点分 |
| 2. 少数派出击 | 己方 6，对手各 9 | 90 秒内赢得据点争夺 |
| 3. 守住这一刻 | 45 秒生存任务、护阵与有限风推 | 倒计时结束仍有己方单位；己方归零立即失败 |
| 4. 绕过花盆 | 对称障碍与两条可走通的路线 | 取得据点胜利，学习集结选路 |
| 5. 风口上的据点 | 预告后出现一次局部风场 | 赢得据点争夺，避免把己方推出优势位置 |
| 6. 小心换队 | 指定单位出现叛变倒计时 | 在叛变扰动下取得据点胜利 |
| 7. 最后一圈 | 有预告的边界收拢、有限时长 | 60 秒后人数领先，或提前只剩己方 |
| 8. 庭院决赛 | 选择最多两种已经学过的事件 | 完成固定规则的最终据点赛 |

一星为完成主目标，另两星是开局可见的额外条件，例如“风推不超过 1 次”“45 秒内获胜”。失败后直接重试相同种子，允许查看一条针对失败原因的提示，不弹一长段通用教程。只解锁关卡、徽记或装饰，不用永久属性奖励破坏公平。

## 6. 现有机制如何取舍

| 现有内容 | 新版去向 |
| --- | --- |
| 循环克制、追逐、转阵 | 核心保留，改善可读性和连续转阵保护 |
| 团队占点 | 重设计得分速度、控制提示、玩家与电脑指令，成为主玩法 |
| 小心叛徒 | 保留为挑战和趣味规则包；至少 3 秒明确预告，变化可追踪 |
| 众生平等 / 响指 | 后续可扩展为“均衡回合”；首版不叠加这项机制，旧版仍可体验 |
| 黑洞 | 改成庭院风旋，在进阶玩法中出现；前摇和范围明确，与据点和出生保护区隔开 |
| 缩圈 | 保留为挑战规则，显示收拢阶段与最终边界；始终有限时，不产生无限死斗 |
| 加速、护盾、团队道具 | 首版以三种主动指挥承接；随机场上补给留待后续，避免初版信息过多 |
| 分裂、反复复活 | 默认改为公开且有限的援军；随机分裂暂不带入新版，严格遵守人数上限 |
| 悬赏、我要打十个 | 第一轮主玩法不叠加，留给后续独立趣味规则包，先验证公平性和解释成本 |
| 上帝之手 | 以明确选点交互的“风推”承接，不沿用全屏触碰立即施法 |
| 国家队 | 新版移除，以原创三方 SVG 身份替代 |

事件每局默认最多一种，挑战决赛最多两种。标准占点先用无随机事件的规则调平衡，再接入扩展。前摇、危险范围和结果提示属于必要信息，不得因性能降级而消失。

## 7. 页面与信息层级

### 7.1 开局页

“调整本局”中展示规模、场景和可用规则包；存在不对称人数或非标准规则时明确显示“自由试验”，而不是到结算时才告知成绩不计入标准记录。

### 7.4 帮助、暂停和战报

- **玩法说明**：三个可切换内容页“谁克谁 / 这一局怎么赢 / 我能做什么”。用可点击的小场景演示一次转阵，配合据点规则与选点操作说明，不与正式局共用时钟。首版不强制插入开局教程。
- **暂停**：继续、玩法说明、重新开始、保存并返回大厅。只有重开或放弃存档需要二次确认；失败的保存留在原页，允许重试或明确放弃。
- **战报**：胜负与主目标在前，随后是人数趋势图、结束时据点分、最近五条关键事件和技能使用次数，例如“风推命中 5 个单位”“重新夺回据点”。不要把偶然相关性写成确定的胜因。
- **重玩**：普通模式“再来一局”生成新种子；挑战“再挑战一次”使用固定开局，通关后可进入下一关；“返回庭院”可调整玩法。
- 弹窗内容在小窗口中可滚动，关闭与主要动作固定可达；系统返回先取消选点，再关闭说明，再暂停，不直接丢弃当前局。

## 8. 手机、折叠与平板：从可用区域决定布局

### 8.1 固定世界，重排显示

标准世界建议为 **720×720 逻辑单位**，所有出生点、据点、障碍、速度、碰撞和技能范围都以世界坐标定义。标准单位直径首轮为 52 逻辑单位，战场显示边长 256 vp 时约为 18.5 vp，手机常见 320–366 vp 战场约为 23–26 vp。

显示时保持等比，地图全部可见，不为了铺满屏幕裁掉关键区域。像素密度只决定清晰度，不能改变实体显示比例。折叠、横竖屏切换只改变画布显示矩形与逆向触点映射，不重新缩放世界里的单位位置、速度或据点。

地图的路线宽度至少允许两枚单位正常通过，障碍布局做可达性验证，出生区域不落入封闭死角。指挥依赖选择区域，不依赖点中直径二十多 vp 的移动角色。

### 8.2 布局与状态规则

| 场景 | 处理 |
| --- | --- |
| 普通手机竖屏 | 上方目标/人数，中间正方形战场，下方技能；次要信息与装饰随高度收起 |
| 矮手机或横屏 | 按剩余空间尝试紧凑布局；宽而矮时标题与控制移入侧栏，不保留占高度的整行顶栏 |
| 平板 / 展开折叠屏 | 战场与操作栏并排，操作区真正变大；配置页支持双栏，帮助采用限宽滚动阅读 |
| 合起后可用外屏 | 只要相当于可玩的手机窗口，就按手机布局正常游玩 |
| 双铰链收起一面 | 根据仍显示的有效窗口与折痕布局，不能因状态是 2、3、12、13 等就拦截 |
| 半折叠有有效折痕 | 先从窗口内的折痕构造可用矩形，选择足够大的连续面板放完整战场；另一面可放状态/操作，但不跨折痕放按钮 |
| 极小窗口 / 面板 | 先收起装饰和次要信息；仍无法同时提供约 256 vp 战场与至少 44 vp 操作目标时暂停，提示展开、旋转或放大 |

256 vp 是初始可读性门槛，必须用 320×480 等小手机样本验证紧凑布局；不能凭设备名称或宽度一道阈值误封正常手机。配置页、说明页和战报仍可滚动查看；空间限制只影响实时战斗。

多折痕需要逐条转换到窗口局部坐标、裁剪并排除窗口外的折痕，不能无条件取数组第一条。根据系统实际提供的信息避让；读不到折痕时依据真实窗口和安全区布局，不能仅凭折叠状态制造遮挡。

形态变化时取消技能预览、结束手势捕获；首版在尺寸、折痕、形态或安全区变化时暂停当前局，保留状态，准备好后手动继续；进入后台、窗口失活或空间不足也暂停，不追补后台时间。正常手机大小的折后窗口不会被阻止继续。倒计时、教程、暂停和结算也必须响应布局变化，且不得自动开启新局。

初步验证矩阵：320×480、360×640、390×844、568×320、844×390、600×720、720×720、768×1024、1024×768、1280×800；再加入左右安全区、横向/纵向/零厚度折痕、多折痕、外屏和分屏，以及系统大字体。所有尺寸指待验证的 vp 样本，不代表已经在这些设备上通过验收。

## 9. 动效、音效与性能边界

### 9.1 反馈有节奏，信息不被效果盖住

| 动作 | 视觉 | 声音 |
| --- | --- | --- |
| 转阵 | 约 120–180 ms 小幅缩放与阵营轮廓变化 | 相邻转阵合并，避免每个碰撞都播声 |
| 技能准备 / 释放 | 清楚的范围圈，释放后 200–300 ms 收束或扩散 | 准备轻提示，释放声音更明确 |
| 据点易主 | 圈色平滑切换，得分状态立即可读 | 一次短提示 |
| 危险事件 | 倒计时、轮廓和图标，避免强烈全屏闪光 | 预告与发生使用不同提示 |
| 胜负 | 简短徽记展开，仍能立即点下一步 | 清楚但不过分突兀的胜负短句式音效 |

局内可控制静音，并与 App 同步；背景氛围音低于操作提示。加载失败不阻止进入可玩游戏，静音或后台时停止对应播放。音效去重、并发和最短间隔独立于绘制，不能每帧新建播放器。

提供减少动态效果选项；关闭装饰摆动、非必要粒子与战报动画，保留判定范围、事件倒计时和输入反馈。

### 9.2 引擎与渲染

- 默认 24 单位，大局 36，首发硬上限仍为 60，包含援军和任何分裂；先保证这些规模，不把增加实体数量当作丰富玩法。
- 固定 60 Hz 逻辑步与屏幕显示驱动分离，AI 目标选择可按约 10 Hz 错峰刷新，移动与碰撞仍逐逻辑步更新。暂停/后台零推进；限制追补步数并记录被丢弃的时间，避免持续卡顿时无限追帧。
- 寻敌和碰撞共用可复用的空间索引，稳定实体 ID，尽量减少热路径分配；评估目标缓存的正确性与拥挤区域最坏成本。不能把所有阵营移动单位当作静止物体休眠。
- UI 只接收汇总状态：人数、计时、分数以 5–10 Hz 或值变化通知；单位位置不放入 `@State`。胜负、技能释放和错误提示即时通知。
- SVG 是素材源。三种单位图形在加载时解析并复用，先验证直接 SVG 图像绘制，再决定是否需要有限尺寸缓存；不在每帧解码、创建渐变或重建整张场景。
- 缓存必须区分 vp、px 和逻辑坐标，记录实际单位直径与纹理尺寸。主题或显示尺度改变才更新必要资源并释放旧资源，避免重演水果显示被密度缩小的问题。
- 静态庭院背景独立一层；动态特效采用有上限的复用队列，初始上限 24 个，重复的微型反馈可以合并。必要的危险与操作范围不参与装饰淘汰。
- 首版提供手动“效果：轻量”，关闭可选技能扩散环，保留危险和选点信息。显示回调期望 60 Hz，最多补 3 步，记录丢弃的追补时间；没有偷偷调整人数、难度或冷却。动态切换绘制档位需有设备数据后再做。

### 9.3 测量与验收目标

新增易筛选的 `CoopArenaPerf` 日志，每 5 秒汇总：版本、模式、种子、单位数、窗口 vp/密度、逻辑步数、回调间隔 P95/峰值、寻敌/碰撞/机制/绘制提交/HUD/存档耗时、效果数与缓存规模；大于 50 ms 的异常输出限频详情。

首轮目标：在选定参考设备上，24/36 单位时主线程游戏回调 P95 尽量低于 10 ms，60 单位时尽量低于 14 ms；常态按 60 Hz 呈现目标验证，记录真实系统帧时间、卡顿比例和连续游玩内存走势。这些是待验证的预算，不是当前测量结果；回调 FPS、Canvas 提交耗时不等同于 GPU 实际呈现帧率。

基准场景覆盖普通追逐、全部单位聚集据点、同帧多次转阵、技能叠加、援军生成和主题/窗口切换。发生卡顿时先依据日志定位，不先删除所有视觉反馈。设备体验继续由用户试玩反馈；未经新的明确要求不操控模拟器。

## 10. 成绩、存档和 App 接入

- 新存档独立使用 `coop_arena_next_v1`，记录规则版本、模式、种子和随机数状态、世界状态、任务、技能、事件时钟与结算上报状态。安全检查通过后恢复为暂停，禁止恢复瞬间自动释放技能。
- 自动保存按稳定间隔与重要事件节流提交，暂停/退出时保存；保存失败显示重试，不无提示地退出。主题、旋转和窗口变化不创建新局或修改种子。
- 新模式成绩与旧版“最高存活数”分开存放。快速乱斗展示胜场 / 完成局数；据点单独记录胜场 / 完成局数；挑战记录每关最高星级。首版战报保留当前局，不提供长期逐局历史。不同人数、不同模式不塞进一个混合最高分。
- 首页统计可用新版挑战星数作为单一摘要，经典版历史最高存活数继续保留，不能直接拿旧值当新纪录。自定义试验不记标准最佳成绩。
- `rpsBattleNext` 可归到现有 `rpsBattle` 的逻辑游戏身份，使收藏家和体验多款游戏的统计不重复计数；新版独立成绩不因此与旧成绩混写。
- 标准观战和固定规则的指挥赛都是正式玩法，允许正常局数与完成成就；自由试验、教学、主动中止不报正式完成。不能把正常指挥赛全部排除，只因玩家用了设计内的技能。
- 正式结束时以唯一 `sessionId` 上报一次；`won` 和 `supportWon` 都以玩家支持阵营获胜为准，平局为 0。挑战通关单独报告任务结果，不与“存在任意胜者”混为一谈。
- 已解锁的旧成就不重置。沿用 App 当前成就规则，正式自然结算上报 `won`、`supportWon`、`elapsedSec`、`conversions`、`score`；新引擎不自行改变成就阈值。
- 首页名称继续为石头剪刀布大作战，场景标签为鸡窝乱斗，不显示“重构中”。首页新增“新版 · 庭院擂台”，旧“鸡窝乱斗”入口与原图标继续保留；最近游玩按独立 ID 进入对应版本。

## 12. 分阶段实施与完成条件

## 14. 场内视觉、接触判定与帧更新修正 · 2026-09-18

用户截图中的“石 / 剪 / 布”不是最终角色设计，而是 `ImageBitmap` 尺寸无效时的文字回退。首版 SVG 只有 viewBox，原生 Image 能按布局显示，但 Canvas 使用的图片缺少明确的固有尺寸；此前资源检查只验证了 XML / viewBox，没有覆盖这条加载分支。

### 视觉与文案

- 资源生成器为所有 SVG 写入明确的 width / height；新增浅深色的 3 种图章。原角色插画保留在队伍卡片和说明中，场内使用带可见外圈的图章。
- 即使设备解码延迟、构造图片失败或提交绘制失败，也使用预编译矢量路径绘制石头、剪刀、布，不再画文字圆点。不让素材失败挡住游戏。
- 图章外圈半径与碰撞半径对应；花盆改为静态场景 SVG，土壤、盆沿、叶片都重新绘制。场内据点用旗帜表示，提示说明放回原生 UI，避免混用 Canvas 中文字体。

### 接触怎样判断

1. 世界固定为 720×720；每个图章半径 26。先通过 72 单位网格寻找邻近对象，再比较圆心距离，少于两者半径之和 52 就发生接触。屏幕像素密度、折叠或画布缩放不改变判定。围栏留白也纳入出生、边界和收圈范围，图章不会半截跨出围栏。
2. 同队只分离。异队按石头克剪刀、剪刀克布、布克石头转阵，总数量保持不变。
3. 同一模拟步先统一检测接触，再统一分离和转阵。修正首版“检查一对就立即移动”的做法，避免后续对象用变化后的坐标查询旧网格。三方同时接触按接触前的身份统一处理，不发生同帧连锁换队。
4. 刚转阵的 0.6 秒保护、护盾抵挡一次和出生保护仍保留；外圈短环表示转阵保护，金环表示护盾。玩法页补充相应说明。

### 流畅度与可定位性

- 保持 60 Hz 固定逻辑步和受限补步；在前后两个模拟状态间做位置插值，缓解回调间隔变化产生的视觉跳步。插值不改存档、碰撞或胜负状态，暂停 / 恢复清理插值旧位置。

## 16. 60 位队员的计算优化 · 2026-09-18

### 本次设备反馈

用户提供 21:34–21:35 的 v3 日志，设备窗口为 377.1×816.0 vp，深色、轻量效果、音效开启。60 位快速乱斗的种子为 `3032101680`，选了临阵换队；实际在游戏时间 2.2 秒清场，所以尚未触发换队事件。

| 指标 | 用户设备上的 v3 数据 |
| --- | --- |
| 回调 FPS / P95 间隔 | 13.0 / 112.13 ms |
| 逻辑平均 / 峰值 | 67.796 / 131.449 ms 每回调 |
| 绘制提交平均 / 总回调平均 | 2.250 / 70.421 ms |
| 步数 / 丢弃追补 | 2.87 步每回调 / 1297.8 ms |
| 抽样寻敌 / 移动 / 碰撞含重建 | 6.297 / 4.073 / 13.044 ms 每步 |
| 可见特效峰值 / SVG 就绪 | 0 / 3 张全部就绪 |

已测回调 CPU 时间主要花在模拟计算；连续补步进一步放大每回调开销。Canvas 提交耗时不代表 GPU 完成时间，不能据此断言设备渲染完全没有压力。此轮优先处理寻敌和碰撞中的重复遍历。

### 实现

- 用固定长度的连续数组替换 100 个动态网格桶。计数排序保持原来的“格子从上到下、从左到右，格内按队员索引”的顺序，将一行范围内的邻居直接连续读取，跳过逐个空格子的循环。
- 每个格子的寻敌、接触查询范围只在创建引擎时计算一次。移动后仍更新格子归属；全部归属未变化时复用排序索引。不会跳过实际碰撞检测。
- 接触位移和转阵工作缓冲固定复用。位移使用 `Float64Array`，保留原有双精度；同帧批量分离和转阵、最深接触优先规则、距离相等的选择顺序保持一致。
- 碰撞内缓存坐标、身份和数组引用；先排除在任意坐标轴上已经隔开的对象，再算圆形距离。移动与碰撞共用本步时间和边界，减少重复调用。
