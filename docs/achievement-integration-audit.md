### A-01：保存失败后重开丢失未确认结果

复现：达到正常结束条件 → 注入成就存储失败（游戏进度仍可保存）→ 页面返回未确认结果 → 点击再来一局/重开 → 恢复成就存储 → 打开成就墙。

结果：五款游戏的新局覆盖了旧局存档，旧局 ID 和事实没有进入可恢复的待补发队列，成就服务中的完成局数仍为 0。并非正常保存时也必然丢失，而是这一故障恢复流程存在缺口。

依据：

- `entry/src/main/ets/gamesNext/minesweeper/MineGardenPage.ets`：`settle()` 与 `newRound()`（复核时 263、362 行）。
- `entry/src/main/ets/gamesNext/glow2048/GlowPage.ets`：`reportEnd()` 与 `newRound()`（308、347 行）；重开会发起异步结算后立即重置棋盘。
- `entry/src/main/ets/gamesNext/blockWorkshop/BlockWorkshopPage.ets`：`finish()` 与 `restart()`（488、422 行）。
- `entry/src/main/ets/gamesNext/fruitMarket/FruitMarketPage.ets`：`finish()` 与 `restartRequested()`（418、368 行）。
- `entry/src/main/ets/gamesNext/warmFreecell/FreecellRoomPage.ets`：`reportWin()` 与 `newGame()`（456、394 行）。

庭院擂台当前工作区的 `preserveResult()`（`CoopArenaPage.ets` 313 行）在成就确认失败时返回 false，`replay()`/`nextMission()`/`toSetup()`会保留旧结果；该路径已验证，不能再将擂台列为同一个重开缺口。

### A-02：游戏保存与成就重试没有连接

复现：探雷或叠数结算时成就写入失败 → 恢复成就存储 → 调用页面实际的 `retrySave()`。

结果：游戏存档保存成功，但成就事件上报次数没有增加，成就墙仍缺失对应记录。当前保留旧局重新进入游戏可以补报；只按这个保存按钮不会补报。

依据：`MineGardenPage.ets:428`、`GlowPage.ets:400` 的 `retrySave()` 仅执行 `save()`。

### A-03：收藏家缺少现存收藏对账

复现：第三个收藏已成功保存 → 成就写入失败 → 重建成就服务 → 调用成就墙实际刷新方法，收藏仍有三款。

结果：刷新只读取成就存档，不检查收藏条件，`global.favorite_three` 仍未解锁。再次取消/添加一个收藏能够重新触发，是绕过办法，不是现有恢复流程闭环。

依据：`AchievementFavoriteEvent.ets` 只接受成功保存的“新增收藏”事件；`Index.ets:459` 的 `toggleFavorite()`负责触发；`Index.ets:687` 的 `refreshAchievementState()`只有读取操作，启动恢复也没有收藏对账。

### A-04：旧版提前确认的结束存档

复现：保留真实结束局的数据和 `reported=true`（例如旧版本在成就落盘前就写入该标记），成就存档中没有这局徽章 → 调用当前页面的结算恢复方法。

结果：探雷、接龙、擂台都没有发出成就事件。接龙两个原先停用的徽章，也不会因为已保留的通关存档满足步数/时间条件而自动补发。

这是旧记录兼容问题，新开一局正常达成仍能解锁。修复时只使用实际保留的胜负、步数、时间等事实；不从历史最高分猜测条件，也不能简单清掉 `reported` 造成合集重复计数。叠数、方块、水果现有恢复检查能补回其局内里程碑，但 `reported` 仍可能阻止补回旧的合集结算。

### N-01：大厅通知被实际展示入口拦截

复现：将一条已保存的解锁通知放入队列，设置 `activeGame='hub'`，调用 `Index.ets:707` 的 `tryShowAchievementNotice()`。

结果：函数提前返回，通知继续留在队列。虽然 `reportAchievementEvent()`允许大厅事件入队，最终展示条件仍禁止大厅。这与成就墙是否已经保存解锁是两件事，不能按“没有弹提示”直接判断“成就没触发”。

## 上一轮已修复的基础接入问题

- 六款新版页面使用异步保存回执，成就落盘成功后才写入本局 `reported`。方块里程碑位也在收到回执后才确认。失败的结果保持未确认，在旧局仍被保留的情况下，恢复该局或再次结算可以重试；重开覆盖的缺口见 A-01。
- 叠数、方块和水果恢复存档时，根据真实局内数据补报已达到的里程碑，覆盖中断动画、旧版提前设置里程碑标记等漏报情况。
- 叠数主动重开不再上报未结束棋盘的 `sessionEnd`，防止错误增加首局与累计局数。
- 新旧游戏 ID 统一映射到同一成就组。水果新版游戏内的解锁通知已接通；大厅事件可以入队，但实际展示仍受 N-01 限制。
- 增加持久化的已结算会话 ID，防止同局重复结算、换事件 ID、超过 32 条短期事件缓存后重放而重复增加局数。
- 擂台使用注册表允许的 `conversions` 事实，练习局不参与正式成就判定。
- 成就存档读取失败时拒绝写入，避免将读取异常当作空账号覆盖已有徽章；用户主动重置仍可恢复损坏存档。

旧存档无需清空。既有解锁记录保留；没有保留详细局内事实的历史对局，不根据最高分猜测或补造限时、步数等成就。会话去重记录从本次更新后成功处理的结算开始保存。
